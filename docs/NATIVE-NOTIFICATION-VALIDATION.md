# 原生消息中心与通知设置恢复验证

## 范围与问题

2026-11-08，在已有微信开发者工具会话中，以本机合成医生583验证消息、已读、页面跳转与个人通知设置。沿用investigate的复现、根因、回归验证流程；不调用真实微信推送、不打开调度、不修改数据库结构。

发现并修复：

1. 消息“全部已读”失败后仍无条件加载列表，加载会清除刚设置的错误。现在只有写成功才刷新，失败保留错误、原列表与未读数；忙碌时重复调用拒绝。
2. 加载中筛选函数仍可修改未读条件，旧请求结果可能展示在新条件下。增加处理函数忙碌保护，与按钮禁用一致。
3. 通知设置保存失败时，错误区“重试”绑定加载，会用服务端旧值覆盖未保存的选择。现在区分加载/保存失败，保存失败按钮为“重试保存”，重复发送用户的原选择。读取、保存期间禁止开关修改与再次加载。

对应文件为`miniprogram/pages/notifications/notifications.js`、`pages/preferences/preferences.js`及其WXML；修改不涉及后端业务算法。

## 证据

回归文件`miniprogram/tests/notification-recovery.test.js`的5个场景修改前全部失败，修改后全部通过；完整小程序68项测试通过，69个JS/53个JSON静态检查通过。

实际原生流程使用`scripts/local/test-native-notifications.js`：

- 正常退出/登录切换合成医生，载入当前通知设置；仅保存失败检查期间将wx.request注入HTTP503，所选开关和错误保留，按钮为“重试保存”。恢复真实请求后点击按钮成功；重新进入页面确认服务端已持久化。
- 通过真实保存接口恢复测试前开关设置。API首次默认值为布尔、已有记录可为0/1，持久化断言按布尔语义比较，不改变旧数据库类型。
- 点击未读发票消息，真实已读接口成功并跳转发票页；回到消息Tab后未读数减少1。
- “全部已读”仅失败场景注入HTTP503，错误、原列表和未读数保留；恢复真实请求后重新点击“全部已读”，未读数归零，切换只看未读显示空态。
- 结束正常登录恢复原模拟器账号并更新私有会话。仅本次合成医生消息被标记已读，未更改其他医生消息。

私有证据在`~/.local/share/petlis/qa/`：`native-notification-ui.json`、`native-notification-preferences-baseline.json`及preferences-error/readall-error/unread-empty截图。错误截图已目视确认提示与原消息同时可见。模拟器脚本没有关闭或重复启动开发者工具。
