# 检测任务改派

核对F19发现：原接口只允许RECEIVED首次分配，功能矩阵原“改派并发仅单测”不能证明改派存在。本轮补齐实际能力。

## 规则与接口

`POST /api/lab/tasks/{taskId}/reassign`：assigneeId、equipmentCode、当前version、reason。

ADMIN或本实验室LAB_STAFF可操作。锁定任务并校验版本，仅TESTING且没有任何本任务结果时可调整；目标必须为该实验室启用人员，设备非空最多64字，原因必填最多500字。过期版本409、已录结果/其他状态409、人员无效400。相同当前配置不新增版本。调整保留原任务ID、首次started_at、订单、实验室、批次及历史。

首次分配与改派均写入既有lin_audit_record，记录前后人员/设备/版本/状态、操作者、原因与时间。改派通知交接双方，消息键包含任务及新版本；失败或过期请求不写审计/通知。原人员随后不能录入结果，继续由既有assigned_to校验保护。

## PC与PHP

PC任务详情增加改派入口、人员选择与分配历史；历史显示人员/设备，原始JSON不直接呈现。按钮按当前任务状态和录入人员显示：已分配本人可录结果，无结果检测中可改派，可退样状态显示退样，RETURNED才显示复检。

PHP共享页在TESTING且无结果时显示改派表单，隐藏当前版本并保留CSRF、任务订单归属、独立LAB_STAFF私有映射和后端正常授权。显示同一审计历史，原PHP操作者前缀留存。普通医生无改派入口；长期工作人员映射仍按原待办处理，不把临时测试映射当作已部署身份体系。
