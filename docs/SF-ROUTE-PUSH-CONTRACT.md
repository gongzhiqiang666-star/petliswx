# 顺丰路由推送契约核对

核对日期：2026-11-07。来源为登录控制台及[官方 RoutePushService 文档](https://open.sf-express.com/Api/ApiDetails?level3=404&interName=%E8%B7%AF%E7%94%B1%E6%8E%A8%E9%80%81%E6%8E%A5%E5%8F%A3-RoutePushService)，不是路由注册或出站下单签名协议。

## 本轮确认

官方文档允许配置JSON或表单/XML推送。JSON示例结构为 `Body.WaybillRoute` 数组；最多10个节点，节点包括 `mailno`、`orderid`、`acceptTime`、`opCode`、`acceptAddress`、`remark` 等。JSON应答为 `return_code` 和 `return_msg`，成功码0000，失败码1000。沙箱定期推送固定节点，不能据此推断实物已到实验室。

控制台当前应用19个速运接口中未见RoutePushService关联，另有云打印接口；没有为本轮关联新API或保存回调地址。公开文档的公共请求参数部分没有足以确认该应用回调认证方式的说明；现有出站“简易MD5”选择不是入站推送已验签的证据。关联/回调配置及官方调测仍需继续核对。

## 已实现

`SfRoutePushParser`独立解析官方JSON结构，限制256KiB、嵌套深度、字段类型/长度及节点数量，严格检查日历日期、重复JSON键和尾随报文；映射既有路由处理所需字段。未知状态码保留，不擅自映射为完成。测试使用合成报文，未连接供应商或写库。

解析不构成身份认证。当前没有注册该类为公开Controller，没有放开SecurityConfig，没有开放公网或写入路由状态。既有SfRouteEventService仍只接受通过已认证网关查询得到的事件。

## 接续验收要求

1. 核对并记录应用侧实际可用的推送认证/请求方法配置；必要时使用官方支持的来源认证或经认证的查单核验策略，不能把可猜的订单号、运单号当作认证。
2. 将回调订单号及主运单号同时与本应用持久请求/运单绑定，校验整批再处理，不能串单；复用现有事件去重和乱序状态机，快递妥投不能直接标记实验室签收。
3. 实现明确的成功/失败应答、重复重试、事务回滚和故障恢复。补未知码、过期/未来节点、取消待确认、跨单、伪造请求和批次部分失败测试。
4. 本地完整验证后再推进官方沙箱工具联调。公网回调地址和安全访问授权按现有项目边界处理，不直接暴露本机完整API；不启调度、不申请生产、不真实寄件。
