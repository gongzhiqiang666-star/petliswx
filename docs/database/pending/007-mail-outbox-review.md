## 必要性与依据

原 PHP `finance/Hospmonthpeport.php::send` 的顺序是生成 PDF → SMTP 发送 → 成功后写 `lin_lb_noticemail.IsSendMail=1`。SMTP 与数据库不能共用原子事务，发送成功后进程崩溃或数据库失败，直接重试会再发一次。

现有 `BusinessNotifications.process/deliver` 将 `lin_notification_event` 解释为微信消息，读取 user/openid/偏好并调用 SubscriptionPush；没有邮件信封、正文附件快照、领取记录、SMTP 结果不明和“邮件接受但业务回调未完成”的恢复状态。不能复用后把邮件错误推给微信，亦不能借审计日志充当可变任务队列。

## 两表用途与影响

- `lin_mail_message` 保存原业务、请求去重、发件人与收件/密送快照、标题正文、附件相对路径及 SHA-256 元数据、源版本、白名单业务回调参数和状态；不保存 SMTP 密码，不复制真实 SMTP 配置。只允许管理员在权限和业务开关开启时操作。
- `lin_mail_attempt` 保存每次领取和投递结果、唯一令牌及人工核对记录。领取先持久化再连接 SMTP；发送结果不明禁止自动重发；SMTP 明确接受后只恢复业务回调，不再次发送。
- 旧表不改。业务回调按已核实 PHP 规则通过应用写入；外发及作业保持关闭，本机试验仅用自建收件服务。
- 新表包含正文和收件人等敏感业务资料，不放入公开静态目录、公开日志或仓库；附件引用只允许 Petlis 私有报告目录，禁用任意路径。
