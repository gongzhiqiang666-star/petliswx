# 小程序 UI 与流程优化方案 V1（待用户确认）

日期：2026-11-07。主目录：petliswx。依据当前 app.json、首页/送检资料/选项/确认页/订单列表 WXML、DESIGN-SYSTEM.md 及标本全链路联调计划。本轮为代码与信息架构审查，未完成新一轮全机型视觉走查，不将推测写成已复现的视觉缺陷。

本方案不修改页面、业务代码或数据库。用户确认后与新旧系统同步、顺丰接口分段开发；旧结构变更仍须单独说明理由并申请，不包含在 UI 方案批准内。

## 一、推荐方向

保留纳博科临品牌与青绿色医疗风，降低大面积墨绿和照片对首屏的占用，用暖白背景、清晰细边框和留白提升亲和力。小程序面向医院医生，第一优先级是“少填、少找、清楚下一步”，不使用宠物商城式促销布局。

- 主色沿用 #0D6E6E，品牌墨绿仅用于小范围识别；背景建议 #F7F8F5，内容白底。颜色最终以关键页模拟器对照为准。
- 正文 28rpx、辅助 24rpx，字段名称与输入内容上下排；金额和状态层级清楚。辅助信息过长允许换行，不为单行整齐隐藏关键信息。
- 白卡细边框、20rpx 圆角、弱阴影；主按钮高度不低于 88rpx，单一主操作。沿用 brand-* 专业图标，统一视觉重量；不新增表情或字符箭头。
- 沿用原生导航、原生 Tab、输入/日期选择、系统文件查看。自定义底部选择层服务于医院、项目、样本选择；保证安全区、键盘避让和长文本可读。
- 登录页缩小品牌照片；表单和登录操作优先进入首屏。保留已有登录与注册方式，不把真实短信、微信未开通包装成成功。

## 二、当前流程判断与调整

现有“选档案→填写资料→选择项目→确认”基础成立，但检测项目可能决定样本要求和必填项。先填写通用样本信息容易在选项目后返工；当前确认页多个信息分组也需避免把关键费用与提交条件埋到底部。订单筛选、搜索、日期筛选同时挤在一行，对窄屏是布局风险，须在模拟器验证。

推荐新流程：
选择/新建宠物档案 → ①实验室与项目 → ②采样与临床资料 → ③核对并提交 → 审核结果 → 现结 mock 支付或月结挂账 → 预约顺丰/绑定已有运单 → 追踪 → 报告。

1. 先选项目再填写该项目要求的采样资料。项目要求必须来自可信配置；未配置时明确提示咨询实验室，不虚构采样规则。一个申请按一个实验室处理，跨实验室项目引导拆单并解释原因，不静默丢弃。
2. 宠物档案复用，不要求重复填写主人、物种、年龄。只补本次送检相关内容；临床史、用药、病理等按项目展示，关键必填不能被折叠隐藏。
3. 切换实验室或删除项目时，提示影响项目、价格及采样要求；保留可复用文本，失效值标记待核对，不悄悄提交旧价格。
4. 草稿保存贯穿三步，返回和会话过期前提示未保存内容；自动保存必须有明确成功/失败状态，开发时先评估现有草稿版本机制，不能冒称已保存。
5. 确认页按“宠物与实验室→项目/样本摘要→费用→提交”排列，各块可返回修改并保留内容。金额细列原价、协议价、优惠、应付；未知价格不显示 0 元。
6. 提交按钮为“提交审核”，结果页给出申请号及下一步；不在审核前显示“立即支付”。现结通过后付款，月结显示“已挂账/归入月结”，按真实状态展示。
7. 顺丰寄件条件与业务审核/支付规则统一由后端判定。已自行寄出的医院可录入已有运单，避免强制二次下单；实验室签收不等同承运商妥投。
8. 驳回先显示原因与需修改区，保留原单号和有效内容。复检/补采显示与原样本、原报告关系，不覆盖历史。
9. 档案回写默认仅影响本次申请快照；是否更新长期档案给出明确选项及变更摘要，避免改单影响历史报告。

## 三、导航与关键页面

建议五 Tab：首页 / 送检 / 报告 / 消息 / 我的。“送检”是业务中心，提供记录与新建入口；草稿在送检筛选和首页续填可达。保留既有路径并统一路由 API，改标签不让旧页面跳转失效。

| 页面 | 优化后首屏与主操作 |
|---|---|
| 首页 | 简洁医院/医生身份、待审核/待支付/待补资料等真实待办、主按钮“新建送检”、最近业务进度；照片与运营位降级，钱包保留在我的 |
| 送检中心 | 第一行搜索与更多筛选；第二行状态分段，不把所有筛选挤成一行；卡片显示宠物、申请号、当前状态、下一步，主操作只一个 |
| 实验室/项目 | 顶部实验室选择、项目搜索与分类、项目价格/周期/采样要求；底部已选数量及费用；项目详情底部层，换实验室先确认 |
| 采样资料 | 宠物摘要固定可见，样本/采集时间/临床资料分组；必填就近提示；扫码与手动输入并存，识别失败可继续 |
| 确认与成功 | 费用清晰、分组可编辑、提交防连点；成功页展示申请号、真实状态和下一步，防止返回重复下单 |
| 送检详情 | 顶部“当前状态＋下一步”；下方分开显示审核/资金、标本物流、检测与报告；顺丰卡、样本条码、报告卡和操作记录各有归属 |
| 顺丰寄件/物流 | 寄收地址、取件时间、服务与费用承担确认；已有运单入口；物流时间线显示承运商原事件，实验室核样另显示；取消失败可重试 |
| 报告列表/详情 | 宠物/项目/日期搜索与筛选，展示已发布、受限、撤回等真实状态；受限页保留必要摘要与明确原因，允许时提供去支付；有效报告一键预览/下载 |
| 消息 | 按待处理优先、业务类型筛选；点击直达具体单据；站内消息与微信订阅授权分开，授权拒绝不挡业务 |
| 我的/财务 | 医院、资质状态、个人资料入口；余额/积分/月账单分清医生与医院归属；发票、优惠券等按频次分组，危险操作二次确认 |

## 四、新旧并行时的交互规则

- 用户不需要选择“PHP 数据/新系统数据”，同一业务对象统一展示。后台留存来源与操作审计，页面仅在同步异常影响下一步时提示“状态更新处理中/更新失败”，提供刷新或人工处理入口。
- 执行动作前复查当前版本。若 PHP 已审核、改价、签收、发布或撤回，提示“该记录已更新，请核对最新内容”，不让旧页面继续覆盖。
- 手动同步期间不伪造“实时同步”。显示最近成功更新时间，失败时保留历史内容并明确标记；待同步的关键动作禁止误导用户重复付款、重复寄件。
- 微信订阅、顺丰回调和订单事件共用幂等边界，消息不重复；原 PHP 操作触发的后续结果也须在小程序正确展示。
