- 模板ID/邮件标题未提供为0/空；邮件正文与报告正文按afterWrite原样写副表，HTML/中文/空格不改、不清洗丢内容。当前只返回JSON，尚未引入HTML渲染页面。
- 原模型并不验证目录项目存在；无目录但原价和实价均显式填写时保留可保存路径，不强行加新限制。无价段又缺金额时受控报错，未造0价。

## 新增技术保障/差异

事务覆盖明细、正文副表和审计；操作者锁+稳定请求号防重，参数行FOR UPDATE串行化本服务的新增。父主单锁避免同单并发覆盖；不更新主单TestFee/SampleStatus，不触发邮件/真实支付/作业。

全局COUNT原逻辑有删除后重复、其他旧PHP/现有新下单路径并发写入的固有限制。此处锁仅协调本迁移服务，不能宣称已协调所有写入者或解决双系统全并发编号问题，需在最终接续统一核验，不为解决它擅自改变原算法或DDL。

新增输入约束：正常发送/审核标志仅0/1、主单/项目编号范围、原varchar长度和金额范围；异常输入与原warning/SQL报错的响应不同，单列兼容，不声称任意隐藏非法输入等价。
