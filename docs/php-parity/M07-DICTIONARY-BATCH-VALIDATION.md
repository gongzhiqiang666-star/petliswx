# M07物种/性别：删除与批量状态迁移

2026-11-08。本轮增加原字典删除、批量状态操作，不改PHP或原表结构；M07导入/选择器/其他字典及两轮整模块复核仍未完成。

## 原源码行为

- Backend trait:del逐条Model.delete、事务提交；物种和性别模型未声明SoftDelete且旧表没有软删除列，因此本轮保持直接删除，不用“禁用”代替删除。
- trait:multi由超级管理员提交实际字段；普通管理员仅限multiFields，默认是status，与字典字段IsActive不同。本轮迁入已核对的IsActive批量状态，其他字段批改及角色映射继续追踪，不能声称通用multi完整等价。
- 原Model.save未改变字段时返回0；multi全部无变化时原提示“未更新任何行”，本轮保留这个结果，不改成成功。
- recyclebin/destroy/restore只是继承候选；当前模型未声明软删除，未把这些方法当作已确认可用的回收站业务，也没有为配合它们改结构。仍保留台账待核实，不默默删除候选。

## 新实现与明确差异

POST /admin/legacy/dictionaries/{kind}/status及/delete，支持单条/多条目标；物种和性别白名单，ADMIN及迁移能力检查。状态仅支持原1正常/0禁用，实际修改行才更新时间，返回实际变更数。删除真正删除原行，同时保存删除前快照、目标ID和请求号审计。

新PC恢复复选、选择数量、批量状态、单条/批量删除；确认页重新读取所选记录，显示Id、中英文名与当前状态。删除明确说明不能在此页面恢复，不虚构回收站。当前页刷新/切换清选择，避免混用不同字典。

技术保护单列：稳定requestKey、目标排序锁、同账号请求锁、快照校验、同事务审计；过期/重复/缺失选择整批拒绝，而不是部分继续。最多1000条一次请求。上述保护与原PHP裸ids接口不同，不改状态含义、名称或金额规则；通用multi其他字段和旧接口全部输入行为尚未通过完整差分。

## 三层开关

legacy-dictionaries参数：

1. enabled：模块只读入口。
2. writeEnabled：新增/编辑及批量状态，需要enabled同时为布尔true。
3. deleteEnabled：额外允许删除，必须上述两项均true且本项也为JSON布尔true。

缺失/false/字符串“true”不扩大权限；不因维护开关开启就自动允许删除。前端schema.canDelete决定显示，后端每次独立核验。结束三项全部false。
