# 迁移后的两轮复核与模块简报

用户2026-11-08明确要求：按计划搬迁PHP能力，迁入后复核两次，逐模块确认核心功能未丢失，最终以简化模块对照报告交付。本要求适用于32组实际业务，不用测试次数替代复核轮次。

## 第一轮：来源、内容、算法及副作用对照

逐模块从原入口、父类/trait、模型回调、JS、SQL/视图、模板/附件、外部SDK倒查，确认每个实际业务有新对应。逐项比较字段/标签/单位、列项/筛选/排序/合计、计算顺序与精度、状态/默认值、身份数据范围、文件/通知/资金副作用及失败行为。

证据包括源位置/哈希、同输入新旧输出、差分测试和界面/文件对照。缺少参考结果、资料或实际实现的项不得通过；只找到同名页面不够。隐藏入口和事件注册必须逐条回到覆盖台账。此轮完成后修复差异，不把“发现问题”标为已解决。

## 第二轮：迁移后重新按实际业务操作核验

第一轮修复合入后，按角色/机构使用新PC、小程序及Java接口重新验证每个模块正常、异常、重复/并发、失败恢复、历史接续与开关关闭。检查实际持久数据、金额/流水、报告/文件、消息和审计，再跑送检到报告完整正常及异常链路。

这轮不能只重复第一轮相同单测：需正常页面、独立黑盒输入、历史/处理中数据及最终流程证据。不能用PHP桥接或直接SQL改状态替代新端业务操作。真实外部依赖与mock/沙箱、摄像头/扫码枪与程序传条码必须分别标注。

两轮均按模块留结论、证据路径、差异及修复复测记录；无核心功能遗漏、无未解释内容/金额/逻辑差异后才标模块通过。最后再做跨模块遗漏审查，确认组合后原功能仍可达。尚未运行的轮次写“未开始”，不能拿本轮编译或7个测试冒充两轮完成。
