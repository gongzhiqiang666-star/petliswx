# M20 邮件业务迁移记录

## 已核实源码与本次实现

- PHP `application/common/library/Email.php::buildAddress`：字符串先将分号替换为逗号，再分割、按原地址去重；显示名为第一个 `@` 之前的内容。不自动去空格、不忽略空项。数组地址输入是另一种契约，尚未接入，不能用字符串规则替代。
- PHP `application/admin/controller/finance/Hospmonthpeport.php`：发件人显示名通过区分大小写的字面替换移除 `@laboklin.cn`，不是只移除域名后缀。
- Java `LegacyMailAddressRules` 已提取上述字符串解析及发件人显示名规则。额外拒绝 CR、LF、NUL，避免邮件头注入；不把无效地址静默删除，后续发送层必须明确报错。
- `LegacyMailAddressRulesTest` 四项测试通过：分隔去重、空项及空格保留、发件人字面替换、邮件头注入拒绝。仅证明规则单元，不是 SMTP 或实际页面验收。

## 邮件配置维护增量

- Java `LegacyMailSettingsService`、`LegacyMailSettingsController` 和 PC `/legacy-mail-settings` 已接通原表查询、新增、编辑、删除。`legacy-mail-settings` 的 enabled/writeEnabled/deleteEnabled 必须是显式布尔真；后端独立校验管理员及开关，前端按能力显示。
- 旧表无自增列，配置锁串行化新系统写入并分配 MAX+1；并行旧系统占用同号时明确拒绝，用户重新打开重试。不改旧结构，不改已有编号。原业务默认编号 1，不自动选新配置替换。
- 密码保留旧表兼容存储；API 不返回 Psw，编辑密码留空保留原值。审计仅记脱敏前值和请求的 HMAC 指纹，不存明文密码；版本和指纹采用现有私有签名密钥并区分用途，密钥轮换后须重新打开页面核对。请求对象的 toString 也脱敏。
- 原字段长度保持；端口限制 1–65535，邮件头字段拒绝 CR/LF/NUL。配置保存不连接 SMTP、不更新报告、财务通知或发送状态。
- 本机数据库业务测试 3 项、原子回滚测试 2 项、地址规则测试 4 项均通过，未跳过；PC 既有测试 139 项通过。真实 PC → Java → 127.0.0.1:13306 验收新增、端口修改、保存重开，数据库证实留空密码保持原值，浏览器异常 0。删除已由数据库业务和回滚测试覆盖，尚未做实际页面删除验收。
- 实际操作使用自建 `.invalid` 服务器和合成密码，未改编号 1；测试数据及审计清理、参数恢复、临时 18082 后端停止。
