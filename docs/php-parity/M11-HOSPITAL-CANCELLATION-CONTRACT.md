# M11 原医院送检取消

## PHP 源码规则 → Java

只读参考 `application/index/controller/User.php::CannelPos`（550行起）：查询本院且 SampleStatus=0 的主单，模型保存 SampleStatus=4。该 index 主单模型没有 beforeUpdate/afterWrite 业务回调，updateTime=false；不调用 admin 主单/明细回调，不更新正文，不退款，不修改医院资金或检测项目。数据库既有触发器仍按原定义执行，不修改或关闭触发器。

原代码没有“已付款不能取消”的限制。Java 新送检流程已有额外限制，两者不混写：本次 `LegacyHospitalCancellationService` 保留**原单**规则，已付款标记不阻挡取消，也不自动退钱；已存在新订单扩展、运单或报告工作流的记录不走此入口，继续由现有新流程处理。这是新旧能力的明确分流，不将新流程限制套到原单。

落点：POST `/orders/hospital-history/{orderId}/cancel`，小程序医院历史原生页的“取消送检”。仅当后端 canCancel=true 时显示按钮；确认框说明保留明细/资金、不自动退款。

## 参数、权限与一致性

- 复用 `legacy-hospital-history` GLOBAL/0 ACTIVE 配置；enabled、writeEnabled、cancelEnabled 三个值均为布尔 true 才可操作。默认关闭，不能靠手工构造请求绕过。
- 原查询医院范围/Java角色鉴权继续生效。操作要求明确医院、待审核旧单及本次展示快照令牌；源主单或新流程关联发生变化时拒绝旧快照。
- 同事务锁参数行、操作人行与主单；条件 UPDATE 再检查医院与状态。只改 SampleStatus，不套用新增退款、通知或报告业务回调。
- 请求号、原请求内容与结果写入已有 Java 审计表。重试相同请求只返回原结果，不再次 UPDATE；换内容重用请求号拒绝。没有新增表/索引。
- 审计写入失败时状态回滚。小程序在响应失败时保留同一请求号与快照，确认成功才刷新；取消确认、并发点击和无操作权限行不会重复发送。
