# M11 PC医院送检历史与取消

## PHP源码规则 → Java → PC

只读依据 `application/index/controller/User.php::Pros`（423行）、`CannelPos`（550行）和 `index/view/user/pros.html`。医院匹配、排除-2草稿、主单ID倒序、样本编号LIKE、状态及含边界的创建日期查询继续由既有Java服务完成。取消沿用原0→4，仅改变主单状态，不改明细、正文、付款标记或资金，不自动退款。原PHP没有按付款标记阻止取消；新PC对已有付款标记明确说明取消不自动退款，不偷偷增加拒绝条件。

PC新增“本院送检历史”，ADMIN/DOCTOR/HOSPITAL_ADMIN且legacyHospitalHistory为true才可见。样本编号、状态、起止日期查询和分页、主单/检测项目详情、审核意见、付款标记、报告状态与取消入口已接通，复用 `/orders/hospital-history` 和 `/{id}/cancel`。本院选择使用既有范围查询，不允许浏览器自行扩大医院归属。

修复共用医院选择器的开关依赖：医院列表现在由医院历史enabled控制，不再要求draftEnabled；历史可在草稿关闭时独立使用，草稿自己的读写/新建/提交开关不放宽。后端医院范围和角色不变。

取消只在服务端canCancel=true时提供，待审核旧单以外、已进入新流程的单据不能借旧入口取消。确认对话框保留原预览令牌；结果不明时同一请求号/内容重试；取消后重新加载当前已应用筛选。日期未完整时不发API请求，翻页不把尚未查询的新输入当成已应用筛选。

## 原报告链接条件不能漏

原页面报告状态文字只在SampleStatus为2/3显示；报告链接条件却为SampleStatus>=2且IsSendMail=1，因此已取消4的单据也可能有原报告链接。后端历史明细增加只读canViewLegacyReport标记保存这条原规则，未将它等同于“报告状态=已出报告”。仍不回传物理路径或不受控的旧PHP/外部URL。

**本次未实现历史报告文件查看/下载。** 详情保留报告状态，具备旧链接条件时说明历史文件访问尚未就绪，不能把有状态或有资格标记冒充可下载报告。真实历史文件映射、权限、兼容旧链接及PDF业务仍按M25/M17/M19和最终完整流程继续完成，不取消该能力。
