# M11 PC本院草稿备注入口

## PHP源码规则 → 新入口

只读核对 `application/index/controller/User.php::SendPro1`（333行）及 `index/view/user/send_pro1.html` 的 `row[Remark]` 富文本字段。原更新限定医院和主单ID，保存备注原HTML；index模型没有后台主单重算/报告/发送更新回调。本次继续使用已迁移的医院草稿服务，不改PHP、不把医院操作转到管理员主单接口。

PC新增“业务管理 → 本院送检草稿”，ADMIN、HOSPITAL_ADMIN、DOCTOR且 `legacyHospitalDrafts=true` 才显示。应用壳为医院角色取得现有医院草稿capabilities；无该角色的实验员/审核员/配送员不会获得入口。后端继续独立鉴权和限制医院，前端隐藏不能代替后端控制。

新增GET `/orders/hospital-history/hospitals` 仅返回当前账号可访问的医院，支持名称搜索和分页，复用现有 CurrentActor 数据范围，不在客户端输入任意医院ID绕过归属。读取不额外过滤停用医院历史；登录/实际保存仍按现有账号和业务权限验证。该查询需现有enabled/draftEnabled开关，未启用时拒绝；不产生新配置表。

页面列出所选医院原-2且未进入新工作流的草稿。点击“编辑备注”通过现有 `GET/PUT /orders/hospital-history/drafts/{id}` 读写，**只提交Remark**，不提交患者资料、医院归属、金额、状态或明细。医生与医院管理员无需ADMIN权限。管理员仍按实际授权范围查询。

备注复用已有本地Tiptap，支持本轮验证的表格/合并单元格、图片引用和文字内容；未编辑时不保存，更新后重开。结果不明时保持同一请求及内容，不让用户换内容重新发起。只读时提供隔离HTML预览，不提供编辑/保存。编辑器无法安全载入时明确保留原文，提供隔离预览且禁用保存；不降级成纯文本覆盖。预览sandbox和CSP禁止脚本及外部加载。

## 未完成与交付边界

此入口只完成医院已有草稿的PC备注维护，不能称PC完整分步送检或M11整模块完成。其他患者字段、项目选择/预览提交仍在已有小程序入口；PC尚未补齐完整分步操作。原生小程序表格/图片等复杂备注编辑及原生基础备注模拟器/真机验收仍未完成，PC入口不替代这项要求。

数据库结构与触发器没有修改，PHP冻结，未操作Mac mini、生产、xsf或其他项目。
