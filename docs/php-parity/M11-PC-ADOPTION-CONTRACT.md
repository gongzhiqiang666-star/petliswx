# M11 PC 旧单明确接入审核

## 来源与边界

原 PHP `index/controller/User.php::SendPro3` 只提交状态0，不设置新系统医生账号、实验室或确认总额；原状态提交已由 M11-DRAFT-SUBMIT-CONTRACT 迁移。本次接入是**已有Java新流程能力**的PC操作入口，不冒充PHP原有实验室绑定。

业务规则沿用 LegacyOrderAdoptionService.submitPrepared/adopt：只接待审核、未付且无下游物流/报告的单据；样本号必须可扫描且不重复；医生属于原医院；原金额与有效明细一致。只有未归属医生且原总额为零时，才允许管理员明确确认明细合计并填入总额。不得静默重定价或更换已有医生。

## 可操作交付

PC“送检管理”待审核行增加“接入审核”，仅ADMIN且独立参数开启时显示。

1. 样本号缺失时显示原因，使用已有“编辑主单”补号，再打开核对。
2. 弹窗对照医院、动物、原送检医师、原总额与明细合计；使用现有两列详情组件，金额只补显示零位，不改原计算/存储值。
3. 管理员明确选择本院可用医生账号、覆盖全部有效项目的已启用实验室，并勾选确认。原DoctorName文本保留，不按名字自动猜账号。
4. 接入后仍待审核，不自动批准。重新打开显示实际医生/实验室绑定，只读，不能重复接入；后续通过已有审核业务处理。

落点 `LegacyOrderAdoptionPreparationService/Controller`、`admin/src/components/legacy-order-adoption.js` 和送检列表入口。

GET `/admin/legacy/order-adoption/capabilities`、GET/POST `/{id}`；参数为 `legacy-order-adoption` GLOBAL/0 ACTIVE，enabled和writeEnabled严格布尔，默认关闭。原兼容 `/legacy/orders/{id}/adopt`、`/submit` 也遵守同一写入开关，不能绕过关闭参数。

新PC专用接口额外要求确认、原单/明细/扩展/下游快照和请求号；同事务执行既有接入与审计，源业务失败或审计失败整体回滚。金额使用服务端原明细字符串与BigDecimal，不在浏览器浮点求和。相同请求按无损JSON内容核对，重复只返回结果。兼容旧参数接口保留原参数行为，未宣称旧客户端拥有新PC全部额外确认交互。
