# 医院历史报告访问增量

## PHP 源码规则 → Java 实现

只读依据：User::Pros 的链接条件（SampleStatus>=2、IsSendMail=1，包括取消单）以及 Project/View::Detail 的目标页付款条件。不能只迁链接条件。

医院登录、数据范围及独立 reportDownloadEnabled 严格布尔开关先校验，再复用 LegacyCustomerViewService.reportPermissionAt 的原规则：现金按整张父单未豁免、未付款且已收样或246项目的 TestPrice 合计判断；月结按原日期截止与2018-09-01起的未付未豁免记录存在性判断，零金额记录也会拦截。父单 IsPayMoney 不能覆盖明细欠款，日期使用既有PHP月份溢出规则。项目、物种、医院仍须存在。

Java LegacyHospitalReportService 提供鉴权文件入口；已有新流程记录时只允许正确关联的已发布报告，不退回旧文件绕过审核。旧文件仅从配置的本机私有目录读取，不请求旧网址、不生成替代原件。响应 private, no-store / nosniff。

PC 历史详情可预览和下载；小程序使用鉴权下载与 wx.openDocument。列表按钮只表示入口资格，付款及文件可用性仍由读取接口判定。默认关闭，不决定旧匿名链接政策。

## 验证

18项Java测试通过（报告7、客户查看4、客户报告4、文件读取3），包含整单兄弟明细欠款、父单已付标记不能绕过、月结零金额欠款，以及已有客户规则回归。174项PC、133项小程序测试及小程序JS/JSON静态检查通过。

实际Chrome医生→真实Java→本机13306：自有有效PDF预览框、下载原名和SHA256一致；取消但无实际欠款、父单未付标记的报告允许读取；跨院/伪造编号/匿名拒绝；删除自有文件后明确404、不生成替代件。订单、明细、正文、两资金池和积分不变，无外部HTTP请求；参数恢复、夹具清理、专用后端停止。此为合成PDF操作，不是历史真实原件或报告生成发布全链验收。小程序尚无模拟器/真机实操证据。
