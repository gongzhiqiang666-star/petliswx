## PHP源码规则与新落点

只读参考（包括继承入口 `application/admin/library/traits/Backend.php::edit` 第137行及控制器 `_initialize` 模型绑定）：`application/admin/view/project/lb_listdiagnosisproject/edit.html` 的 `row[Remark]` 使用 `textarea.editor`；`application/admin/model/LbListdiagnosisproject.php::beforeUpdate` 只清除空的五个日期更新字段，没有对备注重算、发送或报告生成的回调。医院网页 `User::SendPro1` 修改也保存原备注字段，但其新建回调会清空备注，两者不能混用。

新PC“送检管理 → 编辑主单 → 备注”复用已有本地Tiptap编辑器。保留原 `Remark` 内容、原Java字段白名单、版本快照和参数控制，未增加PHP依赖或新接口。未编辑备注时完全不把它放入更新字段，避免仅打开主单就序列化覆盖原HTML；编辑时才取编辑器HTML保存。表格、合并单元格和图片属性由已有编辑器承接，图片数据不上传第三方。编辑器随弹窗销毁。

现有编辑器不能安全载入的内容明确提示原样保留，不创建可覆盖的备注输入；管理员仍可修改其他主单资料。没有静默删掉标签后保存。旧工具栏外观不复制，现有编辑器的全部旧工具能力及复杂历史HTML保真仍以各自未完成清单为准，本次不据此宣布所有编辑器能力完成。

另外复现并修复主单幂等比较问题：原应用审计将canonical JSON按字符串比较，字段顺序不同会把相同重试误判为另一请求。主单新增/更新改用已验证的 `LegacyCanonicalRequest.same`，内容、数字精度或字段值不同仍拒绝。只用于应用请求比较，不用于任何银行/快递签名字节。
