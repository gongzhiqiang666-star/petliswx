# M12 编辑器离线版式对照（专项，未批准产品接入）

## 检查边界

同一独立Chrome、800 CSS像素画布中，分别排版原模板及实验编辑器导出HTML，比较画布尺寸/溢出、table/tr/td/th/img/pre/hr和分页节点的相对位置、宽高，以及边框、内外边距、对齐与分页计算样式。几何容差0.25 CSS像素，计算样式字符串严格对照。这不是截图逐像素比较，不覆盖所有文字Range坐标，也不是原生产PDF引擎/真实编辑NodeView的完整验收。

允许本机内存中的data图片解码；CSP和路由仍禁止外部图片/字体/连接，外部图片未加载，无法据此证明它们上线后的实际视觉效果。合成控制例确认相同版式接受，宽度变化及只改边框颜色均能检出，1×1内嵌GIF确实解码。见editor-layout-smoke.json。

## 已定位并修复的转换问题

1. 原表没有colgroup时，默认编辑器自动生成列宽，改变了原表格的自动分栏。导入记录用空数组明确表示“原来无列组”，导出不擅自创建列宽；真正新建的表仍与原导入状态区分。布局差异44→14。
2. 表格/行组/行之间的HTML缩进被解析为业务内容，生成了额外行、单元格。仅规范原生表格结构节点之间、相邻合法表结构节点间的ASCII空白；单元格、pre、表外空白、非ASCII空白、以及显式改为非表格display的上下文均保留。该规则参照[CSS 2.2 §17.2.1匿名表格对象](https://www.w3.org/TR/CSS22/tables.html#anonymous-boxes)对不产生可见表格内容的空白处理，并有正反例验证。布局差异14→6。
3. 原空布局表被schema的tableRow+约束补出空行；实验改为允许空表，保留原空表，不删除有效数据行。布局差异6→0。空表/不规则表在真实编辑时是否被插件自动修复，以及相应操作能力仍须后续验证。

原生库本已支持空的间隔行，额外回归确认未凭空添单元格；未把已支持行为冒称新增实现。

机器结果：editor-browser-layout-probe.json（原PHP编辑输入）、editor-browser-raw-layout-probe.json（存储技术对照）。原始文本差异、实际内容文本差异和表格缩进差异都有独立字段，不能只读passed判断保真。原PHP输入下688个非data图片实例未加载；技术对照下462个未加载，均未外访。source不同导致数量不同，不混成同一原始数据集的网络证明。
