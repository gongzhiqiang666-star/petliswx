新增 `POST /orders/hospital-history/drafts`，Java `LegacyHospitalDraftService.create` 和 `LegacyHospitalDraftCreationRules`；小程序仍使用本院草稿页，新增“新建医院送检草稿”，创建成功重新读取同一草稿，再沿用项目选择与预览。个人 JSON 草稿仍走原入口。

- 医院取当前账号可访问范围，禁止前端绕过归属；医院需有效。原数据组2、状态-2、创建人字段0，不隐式创建新流程扩展、绑定实验室、生成单号、计算项目金额、扣款或通知。
- 选中品种按 IID 读取中英文并保存副本，主人英文副本取主人原文；修改仍走既有更新路径，不重新推算生日或品种副本。
- 创建回调清空原 UserNO、体重、芯片、采样部位、报告号、备注，三个收发报告日期1900-01-01，费用与各处理标志0。`SaveMedium` 原回调空串在整数存储中对应0，新实现显式写0，不改字段类型。页面创建时不收集随后会被清空的采样部位/备注；部位创建后可修改，备注富文本仍未实现。
- 日期基准沿用 PHP `default_timezone=PRC`，显式使用 UTC+08 的创建时间/当天日期，不依赖运行 Java 的默认时区。本机只读核对 MySQL 当前 CST，与此一致。
- 生日年/月偏移合并后归一化天数；例如2024-03-31减1月得到2024-03-02，2024-02-29减1年得到2023-03-01，不用 Java 直接减月/年造成末日截断。保留空年龄/原页面“ - 岁 - 月”零偏移结果及原文本。
- 额外严格布尔开关 `legacy-hospital-history.draftCreateEnabled` 与既有 enabled/draftEnabled/writeEnabled/draftWriteEnabled 同时为true才允许创建。缺失默认关闭，接口和页面同时受控；不随只读草稿入口开启创建。
- 同一用户同一请求号使用无损 JSON 内容比较，已成功请求返回原单号；不同内容拒绝。创建主单与审计同事务；审计失败回滚主单。客户端响应不明保留同一请求，禁止改内容另发请求号；明确业务拒绝保留错误编号后允许纠正再发。
