# M11 小程序医院草稿备注增量

## 来源与实现范围

仍按 PHP 源码规则 → Java 实现 → 结果验证。原参考 `application/index/controller/User.php::SendPro1` 更新 `row[Remark]`、`index/view/user/send_pro1.html` 的富文本备注，及 `index/model/LbListdiagnosisproject.php`：创建清空备注，修改保存提交的原HTML，没有重新计算生日/品种或邮件回调。本次不修改PHP。

小程序本院已有草稿新增原生 `editor` 组件，可在保存资料前编辑段落、加粗、斜体、下划线、撤销和重做。创建阶段仍不收集随后会被原创建回调清空的备注；创建后再补。后端继续使用既有医院草稿修改接口和权限/参数，不增加表结构、接口或自动外发。

新增 `miniprogram/components/legacy-remark` 与 `utils/legacy-remark.js`：

- 以显式支持集合将旧HTML转换为原生Delta，再读回核对初始化结果；不是把任意旧HTML交给原生组件后假设它完整保留。源文只支持无属性的p、strong/b、em/i、u及纯文本；空段落可重开，常用和数字实体按内容处理。标记失配、未知实体、图片/表格、其他标签/属性不载入编辑器。
- Delta只允许字符串和已支持格式；图片嵌入、未知属性、非法操作或未终止文档拒绝序列化。用户文本转义为HTML，不把输入当可执行标签。初始化不触发修改；未改/撤销回初始语义时交还原始HTML，避免无编辑重写。
- 不支持的原备注维持原文，并明确提示当前不能编辑；已有文字预览继续可用，其他资料可保存，原备注不会进入修改字段。编辑中遇到不支持的Delta则阻止保存/预览，需撤销该次编辑，不能悄悄保存旧备注并假装新编辑成功。
- 仅发送改变的Remark，包含主动清空；保存、重开、版本和同请求防重仍走既有Java。未保存备注阻止预览/提交。只读/保存中、旧页面迟到事件和已卸载组件回调不能覆盖当前编辑态。

微信接口参考采用官方示例仓库 [editor示例](https://github.com/wechat-miniprogram/miniprogram-demo/tree/master/miniprogram/packageComponent/pages/form/editor)，核对原生editor、SelectorQuery获取Context及format使用。官方文档链接本轮工具无法打开，未将搜索结果中的第三方兼容组件文档当微信规范。Delta转换和初始化校验为本项目实现，**不是已获微信原生运行时验证的声明**。

## 未完成及交付限制

此增量是原生基础备注的实现与自动化逻辑验证，尚未验收交付，更不是原备注全量迁移完成。后续必须做微信模拟器/真机的原生初始化、键盘输入、格式切换、撤销、保存重开与异常验证；如表现不同，先修复再启用验收。

PHP原代码、旧表结构、触发器、生产/其他项目保持不动；定时任务和真实短信/邮件/顺丰/支付未启用。品种显示待用户选择、非常规年龄PHP差分及整模块两轮复核等原待办继续保留。整体迁移目标不变。
