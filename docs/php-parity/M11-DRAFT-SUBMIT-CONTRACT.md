## 品种预览差异：等待用户选择

原PHP将 `column('Variety_CN','IID')` 通过 `array_merge([0=>''],...)` 合并，数字键会重新编号，再用原AnimalTypeId取值，可能错位。只读核对本机419行品种，本次读取中413行ID与重排位置不同；**这是字典键差异计数，不是413份送检单已确认错显**。原查询没有ORDER，完整PHP运行差分未完成。

已询问用户：建议按正确品种ID显示，或保留原PHP算法。当前未收到答案，不能默认已批准修正。

- previewVarietyMode=`ID`：按品种ID显示，属拟批准显示修正，不修改原库、价格或报告副本。
- `LEGACY`：保留原数字键重排口径。
- 缺失/其他值：`PENDING`，只提供当前资料与原口径对照，提交关闭。

测试中LEGACY仅为合成夹具的原规则基线，不代表真实开发参数已启用或用户已选择。性别预览仍按原IsActive=0，没有扩展成新字典的1口径。

## 请求恢复补充

发现Java Map.of在独立JVM中有不同对象键顺序（8次独立进程观察到两种），原串比较可能把相同重试误判为不同请求。M11取消、草稿编辑、项目增删及提交改用LegacyCanonicalRequest按JSON对象内容比较，兼容既有审计，不迁移数据。

数字使用BigDecimal/BigInteger无损解析，保留不同数值及数组顺序；有测试先复现默认Double解析会把两个高精度值合并，再修复。该工具仅用于应用请求，禁止用于银行/顺丰签名原文字节。其他模块恢复复核见docs/TODO.md，不能据M11修复宣布全项目恢复完成。
