# M12 实际编辑视图与旧表格保护（专项进行中）

## 发现与修复

之前706模板对照的是导出HTML，不足以证明编辑器实际NodeView相同。真实挂载验证发现默认TableView会重新生成列组，即使导出HTML已经保留原列宽。导入表（legacyColumns非null）改为使用保留原属性/全部列组的标准DOM输出；真正由编辑器内部新建且无原列组元数据的表仍可使用原TableView。没有以静态导出通过代替实际页面检查。

在带空白间隔行的旧表中输入文字，prosemirror-tables自动fixTables会补单元格，改变原布局。锁定版本适配器仅在“本次修改了存在TableMap异常的导入旧表”时，为原appendTransaction提供相同doc基线，从而跳过本次全局自动结构修复；仍调用原选择规范化，并原样保留插件state、鼠标/键盘/粘贴等处理器。没有该条件的正常表/新建表仍走原修复路径。包装具幂等标记，避免继承链重复包装。

空表/空行没有可用于CellSelection的单元格，原选择规范化会报错；对这类合法NodeSelection保留原节点选择，使用户可以删除并撤销恢复。有效表格与有效单元格仍使用原选择逻辑。

这是锁定依赖下的适配，不是完整表格功能完成。多表同事务、异常旧表内嵌新表、复杂粘贴、跨单元格选择、合并/拆分和拖宽后的原列组同步仍须专项；当事务涉及异常导入表时跳过的是本次全局自动修复，不能宣称已实现每张表的独立修复调度。实际选择规范化的空表/行分支另有显式行为，不能一概称完全未变。

## 真实浏览器证据

同一独立Chrome、合成内容、禁止页面外部请求，test:editing现覆盖：

- 旧无列组表在实际页面不生成列组，旧多列组表两组均保留。
- 间隔行所在表格内真实键入X，不补单元格、行数及原height=40不变；原生快捷键撤销恢复文字。
- 在空表外输入文字，原空表保留；有效普通表可以新增行并撤销。
- 空表与空白间隔行可以显式节点选择、真实Backspace删除，并原生快捷键撤销恢复原空结构及行高。
- 原有嵌套行内输入/退格/跨样式替换、Mod-Z/Shift-Mod-Z继续通过，HTML精确恢复，pageerror=0。
