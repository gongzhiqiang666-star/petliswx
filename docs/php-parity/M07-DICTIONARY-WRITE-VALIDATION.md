# M07基础字典：物种与性别新增/编辑迁移

2026-11-08。仅本机新PC与Java实现，不改PHP、已有覆盖层或表结构；M07完整模块和两轮整模块复核仍未完成。

## 原规则与新实现

已核对原Backend trait的add/edit、物种/性别模型及表单、全局default_filter为空、ThinkPHP Model.save的变化判断：

| 原PHP能力 | 新系统情况 |
|---|---|
| 中英文名称必填、原字段长度250/50 | 新PC与Java校验；保留输入原文，不自动改名或截断；长度按Unicode字符计算 |
| 新建默认IsActive=0，显示“禁用”；1为“正常” | 默认值和含义保持，表单使用我们的样式 |
| 创建/更新时间为Unix秒 | 沿用原列，新建同时写入；编辑保留创建时间 |
| 内容未变时Model.save返回0，不推进更新时间，控制器仍返回成功 | 新PC可保存成功，原记录和时间不变 |
| 添加、编辑、重置、保存 | 新PC独立入口与Java接口已实现，不调用PHP业务桥接 |

新增POST /admin/legacy/dictionaries/{kind}、GET/PUT /admin/legacy/dictionaries/{kind}/{id}。读写表名和列名由species/sex白名单确定，不允许任意表/列。

## 技术保护与原业务差异

新请求使用稳定requestKey。同账号请求通过本机用户行锁和READ_COMMITTED事务串行核查旧审计，四个并发相同请求仅一条字典和一条审计；重试返回同一编号，改变内容/操作仍用旧请求号则409。新增和审计同事务，审计失败不遗留字典。

编辑读取六个原字段生成editToken，提交时对照锁定原记录。过期窗口409，保留输入供核对后重新编辑；原PHP没有这种冲突检测。此为明确登记的技术保护，不改变中英文内容、默认状态或计算。新系统有额外操作审计；无变化保存虽不改原记录时间，也保留新系统审计。不能把新增技术保护说成原PHP原生行为。

## 读写参数分开

legacy-dictionaries沿用原只读开关enabled；新增维护必须同时有writeEnabled=true，二者均须JSON布尔值且GLOBAL/0、ACTIVE。没有writeEnabled或字符串“true”不会自动授予写权限。

- enabled=false：隐藏整个模块，直接API拒绝。
- enabled=true、writeEnabled缺失/false/字符串：仍可读取，新增/编辑按钮隐藏，直接写API409。
- 两个布尔均true：管理员可维护；其他角色不能因开关获得权限。
- 写事务持有配置共享锁，参数变更不能在已授权写事务中间造成不确定提交。

前端按schema.canWrite展示按钮；后端每次仍检查。验收结束两开关均false，没有把原只读设置悄悄扩大成维护授权。
