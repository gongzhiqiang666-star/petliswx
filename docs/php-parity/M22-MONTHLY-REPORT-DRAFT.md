# M22 原医院月报查询与账单草稿

## 源码与视图规则

依据`application/admin/controller/finance/Hospmonthpeport.php`的index、send GET、contents、html，以及原`vw_hospmonthreport`→`vw_hospmonthreport3_sendmaildt`→`vw_diagnosisdetail_all`的实际定义。

尽管中间视图名字含sendmaildt，当前实际定义按ReceiveSampleDt归月，不能按名字猜为发送报告日期。底层all视图只取IsCheckPass=0；月报未付是PayStatus2=0，已付是非0且非4，忽略是4。通知来自医院/月对应的lin_lb_noticemail，原有记录和汇总直接读取，不重新计算或修改视图。

send GET使用该医院收到样本日期的整月范围、主单倒序/创建日期倒序清单，原上限20000条。contents的总费用只加未结且非豁免项目；清单表仍显示已付、忽略和免除。标题保留“月份+医院名称+德国纳博科临实验室账单”，正文保留原变量、表格列、金额和状态含义。所有医院联系人可选，原财务联系人限制被注释；真实联系人选择与发送接口尚未在本批开放。

原财务邮件模板不按IsActive过滤。两类模板默认沿用原SELECT返回次序中的最后一条，不擅自指定新默认模板；用户可明确选模板ID。新增实现对显式不存在模板返回404，缺少默认模板则保留未配置状态，不能冒充已有正文。

## 新系统落点

`LegacyMonthlyReportService` / `LegacyMonthlyReportController`：`/admin/legacy/monthly-reports`的列表、月份区间/通知状态筛选、财务模板列表和医院月份草稿。`LegacyMonthlyReportRules`迁移变量替换、未结总费用、原金额大写字符/单位/零处理及账单表格。

PC“原医院月报”支持原金额和通知内容查询、模板选择/重载、账单和邮件隔离预览及正文查看。只有GET读业务接口；不会把预览当发送，也没有手工把通知设为成功的接口。

独立`legacy-monthly-reports.enabled`严格布尔值及Java ADMIN控制入口和接口，默认关闭；`legacyMonthlyReportSend=false`。付款链接缺私有配置时保留原占位符并提示，不能静默删去或生成生产默认地址。超出原20000条范围明确拒绝，不截掉尾部后当作完整账单。

金额通过字符串传输，合计BigDecimal，不在新金额计算中用Double。按源numToRmb保留“壹分整/壹角整”等原有表达和十位限制，不套新标准大写算法。常见参考向量通过，但PHP7.4浮点序列化边界、负数及完整大写原函数差分尚未完成，不称所有金额输入已经等价。已核实本机无可用PHP CLI、原Petlis容器所属Docker daemon未运行；未启动共享Docker/Colima或其他项目。

表格单元格做HTML转义，不让数据当脚本/标签执行；依赖字段内嵌HTML的历史样本仍须对照。HTML预览不代表PDF排版已通过，M17分页选择仍待用户确认。

## 旧分组视图兼容

首次真实数据库测试复现ONLY_FULL_GROUP_BY错误：原视图的notice非聚合字段不满足新MySQL严格分组检查。没有改视图、数据库结构或GLOBAL模式。

`LegacyGroupingSession`仅在当前借用的同一连接上暂时去掉ONLY_FULL_GROUP_BY，其他模式保持；查询结束或抛错均恢复原SESSION值。计数和分页通过该连接的局部JdbcTemplate执行，避免拿另一连接查询或恢复。恢复失败时中止这一借用连接，防止带着临时模式返回连接池。没有接触其他连接、项目或服务器。此项属于旧查询兼容，不改变原分组计算和通知选择；重复通知行造成的旧视图行为不擅自重写，继续历史对照。
