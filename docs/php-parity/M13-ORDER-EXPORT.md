# M13 送检明细导出增量

## 源码与确认差异

只读参考 project/LbListdiagnosisproject.php::export：vwdiagnosisdetail，DiagnosisDetailId倒序，单次10000条；28列按原顺序保留。showPrice使用原sprintf两位显示，付款名称取DealPayMoneyShow并去标签，城市取LbCity::getNameById父级路径；日期直接输出原值，不能套列表show_time清空历史日期。

PHP导出未套用index的数据组及非负状态条件。用户已明确选择“按当前可见范围导出，并记录与PHP的差异”。Java列表与导出共用LegacyMainOrderService.visibleScope，必须配置有效原管理员映射及datagroup，非负状态与当前状态筛选同列表。没有默认全库回退。

## 实现

LegacyOrderExportService/Controller提供admin/legacy/order-export及capabilities；独立legacy-order-export.enabled严格布尔，且原主单读取开关必须开启；角色须ADMIN。PC仅在原列表和导出能力同时开启时显示导出按钮，使用已应用的状态，不受当前分页影响。

原28列与顺序在LegacyOrderExportWorkbook集中定义：主单/明细ID、样本编号、动物/物种/芯片/年龄/病理/生日/采样与畜主资料、日期、性别、德国编号、医院、采样方式、地区路径、检测项及代码、价格、付款状态/代码、豁免、医生。每条检测明细一行，非每个主单一行。字典未找到时沿用原空白，城市未找到为-，缺父级为-/子级；循环城市层级明确拒绝，不递归耗尽。

编号、芯片及原字符串按文本写入，防止前导零/长数字损失或公式样字段被当公式执行，内容保留。LocalDateTime与Timestamp统一输出原年月日时分秒；保留原价格显示精度与空付款代码语义。文件名数据导出加上海时间yyyyMMddHHmmss.xlsx；响应private/no-store、nosniff。

原单次10000上限及最新明细优先保持，按钮明确说明上限，增加“导出说明”工作表记录范围、状态、符合条件总数、实际条数及是否部分导出，避免静默把前10000当全量。没有擅自移除原上限或宣称更大容量已验收。

## 验证

17项后端测试（新数据库3项、工作簿2项、原主单12项）通过；184项前端测试通过。覆盖原28列、编号/芯片/公式样文本、原日期及两位金额、付款/豁免、空状态筛选、数据组和负状态排除、关闭开关/字符串true/非法数据组/角色拒绝、城市路径/缺父级/循环及部分导出说明。

真实Chrome→Java→本机127.0.0.1:13306/laboklin：列表可见1条自有主单，另组和负状态夹具不可见；点击导出，解压实际XLSX核对28列及仅授权范围可见明细、芯片前导零、=开头医生文本无公式节点、日期、金额和付款状态；查询取消状态后导出只有表头。匿名请求被拒绝，无页面错误或外部HTTP请求。自有主单状态/付款/金额等核对未变，参数恢复、合成数据清理、专用后端停止。首次浏览器计数断言把直接HTTP请求计入页面拦截，修正该断言后全链通过，无API响应替换。
