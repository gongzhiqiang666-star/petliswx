# 收样通知：实际投递增量

## PHP 来源及新入口

原业务为 project/LbListdiagnosisproject.php::sendmail、Base.php::lb_dictmailreportnotice 与 common.php::filterContents。标题默认“样本收到通知”；加载通知模板时 detailId=0、type=2，读取原绑定及项目名称聚合；不附文件。SMTP成功后直写主单 IsSendNoticeMail=1，不更新收样日期、主状态、费用、检测明细或报告正文。

新PC“送检管理 → 收样通知”支持当前医院联系人、分页模板选择、加载变量后的正文、Tiptap编辑、确认发送或保存待发送、最近50条投递记录、取消尚未发送的任务及恢复已接受邮件的状态回写。Java入口为 LegacySampleNoticeService/Controller；渲染复用原明细渲染核心，新增组合入口不依赖明细模块的单独开关。

## 参数与发送边界

- `legacy-sample-notice` 的 enabled/writeEnabled/sendEnabled 必须显式为布尔真；前后端分别执行能力与管理员检查。医院联系人限定医院范围，修复旧POST可选其他医院联系人这一授权缺口，记录为安全边界差异。
- 默认SMTP传输关闭。发送还要求私有传输模式可用；本次仅用 TEST_LOCAL 和测试自身分配的127.0.0.1端口。默认原SMTP配置编号1；本机验收通过私有启动参数改用自建合成配置，不改原编号1或真实密码。
- 待发送状态可以取消；已开始、结果不明、已接受和已发送的邮件不能用“取消”伪装撤回。未完成投递存在时不能换请求号再次创建同单通知；同请求重试返回原任务。明确完成后允许按原业务再次发信，保留原全局5秒限频含义。

## 持久化与失败处理

使用已批准的 lin_mail_message、lin_mail_attempt。创建任务、去重及审计在同一事务；请求及源版本采用有用途前缀的HMAC，规范化映射顺序。快照保留发送人、收件人/BCC、最终标题正文、医院与源版本，不保存SMTP密码。

领取和SENDING尝试先提交，再在数据库事务外调用SMTP；入口拒绝从已有事务中发起投递。SMTP结果单独记录，明确接受后再执行原业务直写回调。回调失败保留ACCEPTED，只重试回调，不再次SMTP发送。订单/联系人变化时阻止发送并提示重新核对，医院变化时阻止成功标记回写。SMTP异常保守标记UNKNOWN，禁止直接重发；非法地址/内容标记FAILED。

## 已验证范围

- 6项本机数据库场景：真实绑定替换与无发送入队、请求防重/跨医院联系人拒绝、实际本机SMTP接受及重复调用不再发送、SMTP结果不明时不标记成功且不重发、医院并发变化导致回写暂停并恢复且只发送一次、参数关闭/旧版本/外层事务拒绝，以及换请求号不能绕过未完成任务、取消待发送后可重新创建。
- 相关邮件、模板和共用渲染回归合计57项测试方法通过，均未跳过；PC既有139项通过。这是相关专项及回归，不是整个迁移计划全量验收。
- 实际PC → Java → 隔离MySQL → 自建SMTP通过：选择联系人、加载模板、编辑中文正文、确认发送、API重试返回SENT。自建SMTP只接收一次，无AUTH，无附件；收到的正文包含页面编辑后的内容。
- 比较合成主单全部字段，只有IsSendNoticeMail从0变1。旧TestFee为DOUBLE，按原字段数值比较，未改成字符串两位小数规则。浏览器异常0；合成记录、审计与临时SMTP配置已清理，开关恢复，临时Java/SMTP进程停止。
