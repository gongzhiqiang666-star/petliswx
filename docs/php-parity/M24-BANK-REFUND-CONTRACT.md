# M24 原网银退款与退款查询接续

## PHP 源码规则 → Java 实现

冻结只读来源 `application/index/controller/Project/Pay.php::refund/refundQuery` 第211–235行。另在原application/index/controller及admin/controller检索function refund、refundQuery及trxAmt，未发现另一套原网银退款状态回写实现。

原代码只调用固定2022旧单、金额1分的示例：refund使用商户+当前时间+随机后缀的merOrdrNo、原支付单号oriMerOrdrNo、当前yyyyMMddHHmmss的oriTrxDt，以及整数trxAmt；refundQuery也传原支付单号和当前时间，无trxAmt。源代码不解析退款结果、不记退款流水、不改临床付款标志或任何资金池。

现在保留两种原协议能力，改为选择当前账号已核实付款的原支付意图、输入退款金额及原因，不复制示例单号和1分。金额用精确整数分计算，wire trxAmt仍为整数，未误发成字符串；请求时间与查询原支付单号按PHP保留。

## 当前可操作交付

`LegacyBankRefundService`、`LegacyBankRefundDispatchService`、`LegacyBankRefundController`及PC原网银付款页的“申请退款 / 我的退款申请”：

- 保存退款意图，原请求键与内容一致时恢复原记录，不重复预留。不同内容用同键409；同原单的所有未撤销申请合计不能超过原实付整数分，结果不明及已返回记录也保留额度。
- READY仅保存未发。确认后先持久化SENDING和唯一token，再在事务外调用refund。超时、断开、坏签名等转UNKNOWN，不再发送同请求；只允许refundQuery。
- 查询先QUERYING并持久化70秒租约，禁止并行查询；使用原支付单号，保留每次领取次数和最后验签通过的银行msgBody。
- 银行返回记为BANK_RESPONSE，表示“已收到银行返回，请核对”，**不等于退款成功**。验签后同时保留msgBody结构和独立文本快照，避免MySQL JSON浮点及浏览器JSON数字转换改变显示精度；显示精确文本并HTML转义，不丢掉未识别的业务字段，也不据未知结果码自动冲销。
- 只有READY可以撤销，CANCELLED不再占申请额度。撤销仅针对本系统未发的申请，不伪造银行撤销或退钱；撤销后同键重试仍返回原CANCELLED，不新建。
- 记录分页、查询和刷新恢复；确认框重开时不明请求继续用同键，修改金额/原因须先核对原请求。

接口 `/admin/legacy/bank-refunds`：GET分页、POST保存；`/{key}` GET、`/{key}/send`、`/query`、`/cancel` POST。ADMIN及本人请求控制。config.enabled与refundEnabled控制申请/发送/撤销，refundQueryEnabled独立控制查询；前后端都严格检查，后端商户配置不能由浏览器替换。

继续复用lin_order_idempotency的独立LEGACY_BANK_REFUND命名空间及JSON，未新增或修改结构。原付款记录与退款意图分开，未借用微信订单或混淆医院/个人资金。
