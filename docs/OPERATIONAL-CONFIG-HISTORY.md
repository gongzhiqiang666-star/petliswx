# 运营配置历史与恢复

运营管理新增“运营参数”页签；积分规则及运营参数均有“历史与恢复”。显示操作人、原因、时间及版本，分页查看；选择修改前/修改后快照，对照当前值与待恢复值，填写恢复原因，再恢复为新版本。历史缺失快照时明确禁止自动恢复，不伪造旧值。

## 数据与接口

复用既有 `lin_operational_config` 与 `lin_audit_record`，没有结构变更。当前管理入口限定GLOBAL/0配置，不将其他机构范围的数据误作全局配置编辑。

- 创建配置：审计after_json保存版本0及完整值。
- 更新配置：同事务保存before_json/after_json，包含version、scopeType、scopeId、value。
- `GET /api/admin/operations/configs/{key}/history?page=0&size=20`：返回当前全局配置与分页审计记录，包括早期无快照记录。
- `POST /api/admin/operations/configs/{key}/restore`：`auditId`、当前`version`、必填`reason`（最多500字），可选`snapshotSide`为BEFORE/AFTER，默认AFTER。

服务端要求既有运营审核权限；锁定当前全局配置，校验当前版本、来源审计的配置键/资源/动作及全局快照。恢复增加版本号，不覆盖审计历史；新审计保留恢复来源ID及快照位置。跨配置来源不允许、无快照不允许、过期版本409。相同版本的并发请求只有一次成功；异常由事务回滚。

这只恢复参数值，不倒退过去的账务、积分、订单、通知或寄件结果，也不启用任何定时任务。所有业务消费端对配置的使用仍须逐项验证；本功能不代表后续PHP全量迁移的模块开关已实施。旧审计中从未保存的值无法恢复，但旧配置自本次首次修改起会保存其修改前值。
