# 顺丰取消后保留历史的再次寄件

状态：2026-11-08用户明确批准，006已在本机隔离副本执行并通过原行/其他结构核验，详见SF-ATTEMPTS-006-EXECUTION.md。业务实现与官方沙箱再寄验收仍待完成，当前仍禁止覆盖原请求/运单再次寄件。

## 已核实的约束

本机SHOW CREATE TABLE确认：`lin_shipment.uk_shipment_order(order_id)`每单仅一运单，`lin_sf_request.uk_sf_order_operation(order_id,operation)`每单仅一组CREATE/CANCEL。直接放开按钮会被约束拒绝；删除旧请求或覆盖tracking_no会破坏旧面单、路由、取消记录和幂等保护。两表均为本项目新增表，原PHP表无需结构调整。

采用独立寄件次数和活动运单标识，精确DDL为`docs/database/pending/006-sf-shipment-attempts.sql`。旧行默认为第一次；旧运单保留原ID，后续运单创建新ID，每单至多一个is_current=1，其余为NULL。每次CREATE/CANCEL由(order_id,attempt_no,operation)独立去重；不将operation改成带编号的非业务值。

## 实现顺序

1. 先提交兼容读取：按订单读取只取当前运单；旧运单按ID仍可授权查看，历史列表独立可达。PHP桥接、小程序、PC、标签、路由、检测收样共同核对。未批准前不部署依赖新列的SQL。
2. 新增明确的再次寄件动作与原因，默认关闭参数；权限限ADMIN，需前一次承运商明确取消且本地CANCELLED，订单仍审核通过并满足支付/月结条件、未退款/作废且未开始实验。
3. 请求必须引用前一次CREATE的ID/次数，锁订单后分配下一次；并发同一前序只能获得同一新请求，不因页面重试连续增加次数。相同请求不同联系人/地址409，不重新下单。外部订单号后续使用独立后缀，第一次维持兼容旧号；最多次数及长度做明确校验。
4. 网络仍在数据库事务外，UNKNOWN/SENDING只核对、不重发。得到明确主运单后，短事务将前次is_current置NULL并创建新运单；若事务失败，原请求保留成功结果，核对可恢复绑定。未绑定前旧取消运单仍只读，不允许操作。
5. 各次面单按独立shipment_id缓存；已取消历史面单继续撤权，不能作为新面单下载。旧路由回调只归属旧运单，不更新当前运单；每次取消只影响本次，不能因历史CANCEL记录阻止新运单。
6. 医生/PC/PHP展示当前物流与历史次数、单号、状态、原因、时间；新旧系统同单操作均走一致入口，不新增送检单、不重复计价/收费。取消和再寄不改原订单主键与报告ID。

## 验收门槛

覆盖首次旧数据兼容、取消未知/拒绝/成功、两人并发再寄、换参数重试、响应丢失、成功但本地绑定失败、重复核对、前次ID过期、跨医院/角色、退款/结果后拒绝、旧面单撤权和新面单独立、旧路由乱序/重复、历史记录不变。官方沙箱按isDocall=0验证第二次下单、标签、取消，再由PHP/新端接续至报告；不能仅测试假网关后宣称对接完成。

批准后仅本机隔离副本执行，备份并用schema_guard对比原PHP结构未变。DDL非事务，分步失败必须停止；多次寄件产生后不可删历史恢复旧唯一索引，先关参数并保留兼容读取版本。最终报告单列两张新增表的具体结构调整、数据验证和回退限制。
