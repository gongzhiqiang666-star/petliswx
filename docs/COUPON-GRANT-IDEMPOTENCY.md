# 发券并发与请求内容校验

2026-11-08，F07发券专项，仅本机隔离副本、合成医生及新合成券。

## 真实问题

新合成券9、同一管理员/同一请求号四并发，原实现返回4个不同用户券ID，落4张用户券/4条发放审计；换收券人重放同号仍200并返回前一个人的券。根因：首次普通查询先建立RR快照，等待收券人锁后再次普通查询仍看不到已提交记录；请求又没有与原收券人/券模板核对。不同目标锁也不能串行相同请求。

## 修改

发放先锁操作人账号，再按操作人+请求号当前读审计与实际用户券，事务使用READ_COMMITTED。请求命名空间明确为单个发放操作人；同操作人相同请求必须是相同模板与收券人，才返回已有用户券。改内容409；历史同一请求已出现多条记录时409要求核查，不自动选一条、清理或再发。未找到请求才验证目标、锁券模板/库存并发放，收券人没有余额/积分变更，不再先锁目标导致跨目标无法串行。权限及库存锁保留。

没有修改券金额、门槛、有效期、协议定价叠加或下单保留/消费/释放规则。券停用后重放已成功请求仍返回原发放ID，不新增券或再扣库存。没有修改表/索引或历史发放记录。
