# 资讯下架通知拦截与首页弹窗频控

## 行为与实现（2026-11-08）

下架事务将该资讯的pending/failed/unconfigured通知改为skipped，清除下次发送时间，每条增加CONTENT_UNAVAILABLE记录；保留站内消息和已发送记录。重复下架/撤销不重复记日志。手动重试会核实资讯仍已发布且时间生效，下架、草稿、缺失、未来发布时间或错误业务关联均不可发送。

发送任务在逐条事务中先锁资讯、再锁通知事件，与发布/下架保持一致顺序；重新检查事件可处理状态后才发送。争用未取得的事件不计入已处理数，批次仍有50次上限。为该任务单独使用READ_COMMITTED，不修改全局隔离级别；已经取得锁开始发送的请求不能撤回，下架等待其事务结束，不能承诺撤回已发出的消息。

修复另一边界：资讯标题上限250字符，而通知列仅200字符，原实现可能在广播入库时报长字段错误。现在仅通知标题按Unicode码点截到200，不截断emoji代理对，原文章完整标题不变。回归先失败（230/200）后通过。

首页弹窗按账号隔离记录，同一资讯每账号/设备一次，不同资讯默认至少间隔24小时；系统弹窗返回后才记录频次，显示失败不消耗次数；隐藏首页或请求期间切换账号不会展示旧请求结果。并发检查只展示一次。已有全设备旧键不再用于抑制其他账号，升级后可能对当前账号额外提示一次。

运营参数可使用已有配置管理入口，GLOBAL键`article-popup`，例如：

```json
{"enabled":true,"minimumIntervalHours":24}
```

间隔范围1–720小时，enabled=false关闭；格式或范围无效时不弹，未配置使用24小时。配置读取只接受ACTIVE记录，无需新增表或自动插入配置。
