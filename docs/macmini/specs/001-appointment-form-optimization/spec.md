# Feature Specification: 预约信息填写菜单优化

**Feature Branch**: `001-appointment-form-optimization`
**Created**: 2025-12-30
**Status**: Draft
**Input**: User description: "预约信息填写菜单
1.体重不是必填、年龄自动计算，改为选择，用户选择几岁几月，最终存入数据库时岁和月替换为Y、M。
2.选择检测项目页面还有全部加载数据的情况，考虑到性能必须按需加载
3.预约预览界面很多字段没有赋值，核实
4.样本类型采用和宠物建档中品种一样的选择框

最后预览并提交按钮点击时时才更新主表状态：
  - SampleStatus - 从-2更新为0（待审核）
  - ReportNO - 生成德国报告编号（通常以RAB开头）"

## Clarifications

### Session 2025-12-30

- Q: 年龄选择器UI交互模式 → A: 两个独立选择器并排显示（左侧年份0-30，右侧月份0-11）
- Q: 检测项目搜索触发机制 → A: 实时搜索，用户输入每个字符后立即触发搜索（带300ms防抖优化性能）
- Q: 订单预览页面空值字段显示方式 → A: 显示标签 + "未填写"（灰色文本），确保用户清楚知道哪些字段未填写

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 优化年龄和体重输入方式 (Priority: P1)

用户在填写宠物检测预约信息时，需要能够灵活输入宠物的年龄信息，并可以选择性地提供体重数据。

**Why this priority**: 这是核心数据收集流程的改进，直接影响用户能否完成预约。年龄是必填项且格式需要规范化，体重改为非必填减少了用户的填写负担。

**Independent Test**: 可以通过填写年龄和体重（或不填体重）并验证数据正确保存到数据库来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户在预约信息填写页面，**When** 用户选择年龄为"3岁7个月"，**Then** 系统存储为"3Y7M"格式到数据库
2. **Given** 用户在预约信息填写页面，**When** 用户不填写体重字段，**Then** 系统允许继续操作且不显示错误提示
3. **Given** 用户在预约信息填写页面，**When** 用户填写了体重为"15kg"，**Then** 系统正确保存该值到数据库
4. **Given** 用户选择年龄为"5个月"，**When** 提交表单，**Then** 系统存储为"5M"格式

---

### User Story 2 - 检测项目按需加载 (Priority: P1)

用户在选择检测项目时，系统应该分页加载数据而不是一次性加载所有项目，以确保页面响应速度和流畅的用户体验。

**Why this priority**: 性能优化直接影响用户体验，尤其是在检测项目数量较多的情况下，一次性加载会导致页面卡顿。

**Independent Test**: 可以通过打开检测项目选择页面并观察数据加载行为来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户进入检测项目选择页面，**When** 页面首次加载，**Then** 只显示前20条检测项目
2. **Given** 用户滚动到页面底部，**When** 到达加载触发区域，**Then** 系统自动加载下一批检测项目（20条）
3. **Given** 用户在搜索框输入关键词，**When** 进行搜索操作，**Then** 系统在全部数据中查找并显示匹配结果
4. **Given** 检测项目已全部加载完毕，**When** 用户滚动到页面底部，**Then** 不再触发加载操作

---

### User Story 3 - 样本类型选择器优化 (Priority: P2)

用户在选择样本类型时，使用与宠物建档中品种选择相同的独立页面选择器模式，以提供一致的交互体验。

**Why this priority**: 提升交互一致性，样本类型选项较多时独立页面选择器能更好地展示选项。

**Independent Test**: 可以通过点击样本类型选择并验证打开独立页面来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户在预约信息填写页面，**When** 点击样本类型选择框，**Then** 系统导航到样本类型独立选择页面
2. **Given** 用户在样本类型选择页面，**When** 选择一个样本类型，**Then** 系统返回预约信息填写页面并显示选中的样本类型
3. **Given** 用户在样本类型选择页面，**When** 不做选择直接返回，**Then** 预约信息填写页面的样本类型保持之前的状态

---

### User Story 4 - 订单预览信息完整展示 (Priority: P2)

用户在订单预览页面能够看到完整的订单信息，包括所有已填写的字段，以便在提交前进行核对。

**Why this priority**: 信息完整性是用户信任的基础，用户需要在提交前确认所有信息正确无误。

**Independent Test**: 可以通过填写完整信息后进入预览页面并验证所有字段正确显示来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户填写完所有预约信息，**When** 进入预览页面，**Then** 显示宠物姓名、品种、性别、年龄、体重等所有基本信息
2. **Given** 用户填写完所有预约信息，**When** 进入预览页面，**Then** 显示样本类型、采样部位、采样日期等样本信息
3. **Given** 用户填写完所有预约信息，**When** 进入预览页面，**Then** 显示畜主姓名、送检医师等配送信息
4. **Given** 用户填写完所有预约信息，**When** 进入预览页面，**Then** 显示已选择的检测项目及其价格
5. **Given** 用户在预览页面，**When** 查看信息展示，**Then** 所有字段都正确赋值，不显示为空或undefined

---

### User Story 5 - 订单提交时更新状态和生成报告编号 (Priority: P1)

用户在预览页面点击"提交订单"按钮后，系统将订单状态从草稿更新为待审核，并生成唯一的德国报告编号。

**Why this priority**: 这是订单生命周期管理的关键步骤，确保订单进入审核流程并获得唯一标识。

**Independent Test**: 可以通过创建订单并验证数据库中的状态和报告编号来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户在订单预览页面点击提交，**When** 提交成功，**Then** 数据库中订单状态从-2（草稿）更新为0（待审核）
2. **Given** 用户提交订单，**When** 订单创建成功，**Then** 系统生成格式为"RAB{年}{订单ID}"的报告编号（如"RAB20251"）
3. **Given** 订单已提交，**When** 查询订单详情，**Then** ReportNO字段包含生成的报告编号
4. **Given** 同一年创建多个订单，**When** 每个订单提交，**Then** 每个订单拥有唯一的报告编号

---

### Edge Cases

- What happens when 用户只选择年龄的年份而不选择月份？（例如只选择"3岁"）
  - 系统应存储为"3Y"格式

- What happens when 用户年龄输入超过合理范围（如200岁）？
  - 系统应显示错误提示，要求重新输入

- What happens when 检测项目数据在分页加载过程中被更新？
  - 系统应在下次加载时获取最新数据

- What happens when 用户在样本类型选择页面未选择就返回？
  - 系统应保持原有的样本类型值，不进行清空

- What happens when 用户在预览页面发现信息错误并返回修改？
  - 系统应保留所有已填写的信息，允许用户修改

- What happens when 订单提交时后端生成报告编号失败？
  - 系统应向用户显示明确的错误信息，不创建订单

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供两个并排的独立选择器用于年龄选择：左侧选择器显示年份选项（0-30岁），右侧选择器显示月份选项（0-11个月），用户可以独立点击每个选择器进行选择
- **FR-002**: 系统必须将用户选择的年龄转换为"Y/M"格式存储到数据库（例如"3Y7M"、"5M"）
- **FR-003**: 系统必须允许体重字段为空值，不强制要求填写
- **FR-004**: 系统必须在检测项目选择页面首次加载时只加载前20条数据
- **FR-005**: 系统必须在用户滚动到页面底部时自动加载下一批数据（每批20条）
- **FR-006**: 系统必须在用户输入时立即触发搜索，使用300ms防抖优化性能，在全部数据中查找并显示匹配结果
- **FR-007**: 系统必须在点击样本类型选择框时导航到独立选择页面
- **FR-008**: 系统必须在用户从样本类型页面返回后正确显示选中的样本类型
- **FR-009**: 系统必须在订单预览页面显示所有字段标签，对于空值的字段显示"未填写"（灰色文本），确保信息完整性
- **FR-010**: 系统必须在用户点击"提交订单"按钮时将订单状态从-2更新为0
- **FR-011**: 系统必须在订单提交时生成格式为"RAB{年份}{订单ID}"的报告编号
- **FR-012**: 系统必须验证年龄输入的合理性（不超过100岁）
- **FR-013**: 系统必须在检测项目加载失败时向用户显示友好的错误提示
- **FR-014**: 系统必须在样本类型未选择时提示用户进行选择

### Key Entities

- **预约订单 (lin_lb_diagnosisproject)**: 包含宠物信息、样本信息、配送信息、状态和报告编号
  - 年龄: 格式"Y/M"，例如"3Y7M"
  - 体重: 可选字段
  - 状态: -2（草稿）→ 0（待审核）
  - 报告编号: "RAB{年}{订单ID}"

- **检测项目明细 (lin_lb_diagnosisdetail)**: 关联订单的检测项目列表
  - 检测项目ID
  - 价格信息
  - 状态信息

- **样本类型 (lin_lb_sampletype)**: 样本类型选项
  - 样本类型ID
  - 样本类型名称

- **检测项目 (lin_lb_infotesttype)**: 可选的检测项目列表
  - 检测项目ID
  - 检测项目名称
  - 价格信息

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能够成功选择年龄并正确保存为"Y/M"格式的比例达到100%
- **SC-002**: 用户能够在不填写体重的情况下成功提交订单
- **SC-003**: 检测项目选择页面的初始加载时间在1秒内完成
- **SC-004**: 用户滚动检测项目列表时，下一批数据的加载时间在500毫秒内完成
- **SC-005**: 订单预览页面的所有字段显示完整率（无空值或undefined）达到100%
- **SC-006**: 用户点击提交后，订单状态正确更新为"待审核"的比例达到100%
- **SC-007**: 系统生成的报告编号格式正确率为100%
- **SC-008**: 用户能够成功使用样本类型选择器并正确选择的比例达到100%
