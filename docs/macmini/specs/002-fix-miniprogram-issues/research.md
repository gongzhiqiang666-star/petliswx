## 决策1: 预约检测流程的页面设计

### 决策

采用**多步骤向导式流程**: 选择宠物 → 填写信息 → 选择项目 → 预览 → 提交

### 理由

- **用户体验**: 符合用户心理模型,逐步引导完成复杂任务
- **数据验证**: 每个步骤可以独立验证,降低错误率
- **微信小程序惯例**: 大多数小程序采用类似流程(如外卖下单、购票流程)
- **可维护性**: 每个步骤独立页面,职责清晰,易于维护和测试

### 替代方案

- ❌ **单页长表单**: 信息过多,用户容易疲劳,移动端体验差
- ❌ **弹窗/模态框**: 不适合多步骤复杂流程,屏幕空间有限

### 技术实现

- 使用`wx.navigateTo()`进行页面跳转
- 通过URL参数或全局变量传递宠物ID等数据
- 使用`wx.setStorageSync()`临时存储表单数据,防止数据丢失
- 预览页面从storage读取所有步骤数据并展示

## 决策2: 后端API字段命名适配

### 决策

**直接使用后端PascalCase字段名**,不做任何映射转换。

### 理由

- **用户明确要求**: "字段命名以后端返回字段为准,后端提供标准WebAPI接口"
- **简化维护**: 避免映射层,减少bug和同步问题
- **性能**: 零转换开销,直接渲染
- **后端标准**: PascalCase是.NET/C# WebAPI的标准命名方式

### 替代方案

- ❌ **前端统一转camelCase**: 增加复杂度,每次API变更需同步修改映射逻辑
- ❌ **混用策略**: 导致代码混乱,开发者困惑

### 技术实现

```javascript
// 错误示例(不要这样做)
const animalName = data.AnimalName; // 不转换

// 正确示例
const AnimalName = data.AnimalName; // 直接使用
```

```xml
<!-- WXML模板中 -->
<text>{{item.AnimalName}}</text>  <!-- 使用后端字段名 -->
```

## 决策3: 检测项目分类与筛选UI

### 决策

采用**顶部横向滚动分类标签 + 列表展示**的模式。

### 理由

- **行业标准**: 淘宝、京东、美团等主流电商App都采用此模式
- **空间效率**: 横向滚动标签节省垂直空间
- **操作便捷**: 单手操作友好,适合移动端
- **扩展性**: 易于添加新分类

### 替代方案

- ❌ **侧边栏分类**: 占用屏幕空间,压缩内容区域
- ❌ **下拉筛选器**: 不够直观,隐藏选项
- ❌ **底部Tab切换**: 与小程序底部导航冲突

### 技术实现

- 使用`<scroll-view scroll-x>`实现横向滚动标签
- 分类标签选中状态高亮显示
- 点击分类切换时过滤数据列表
- 顶部提供搜索框支持按名称搜索

## 决策4: 错误处理策略

### 决策

采用**快速失败 + 手动重试**策略。

### 理由

- **用户明确要求**: "失败后立即显示错误提示,不自动重试"
- **用户控制权**: 让用户决定是否重试,避免无意义的等待
- **透明性**: 明确告知用户问题,而不是默默重试
- **性能**: 避免无效的API调用,节省资源

### 替代方案

- ❌ **自动重试3次**: 用户不知道发生了什么,体验差
- ❌ **指数退避重试**: 增加复杂度,用户仍需等待

### 技术实现

```javascript
// API调用示例
async function loadData() {
  try {
    const data = await api.getData();
    this.setData({ data });
  } catch (error) {
    wx.showToast({
      title: '加载失败,请重试',
      icon: 'none'
    });
    // 显示重试按钮
    this.setData({
      showError: true,
      errorMessage: error.message
    });
  }
}

// 重试按钮
onRetry() {
  this.loadData();
}
```

## 决策5: 表单数据临时存储

### 决策

使用**小程序本地存储(localStorage)**临时保存表单数据。

### 理由

- **防止数据丢失**: 用户意外返回或退出时数据不丢失
- **多页面共享**: 不同页面可以访问相同的表单数据
- **离线友好**: 网络问题时用户可以先填写,稍后提交
- **微信小程序标准**: `wx.setStorageSync()`是官方推荐方式

### 替代方案

- ❌ **URL参数传递**: 数据量大时URL过长,不安全
- ❌ **全局变量(app.globalData)**: 小程序销毁后数据丢失
- ❌ **页面栈传递**: 页面跳转后数据难以回传

### 技术实现

```javascript
// 保存表单数据
wx.setStorageSync('order_form', {
  petId: this.data.petId,
  sampleInfo: this.data.sampleInfo,
  testItems: this.data.testItems
});

// 读取表单数据
const formData = wx.getStorageSync('order_form') || {};

// 清理表单数据
wx.removeStorageSync('order_form');
```

## 研究总结

### 关键发现

1. **预约流程**: 多步骤向导式是最佳实践,符合用户期望
2. **字段命名**: 直接使用后端字段名,简化开发维护
3. **UI模式**: 横向滚动分类标签是行业标准方案
4. **错误处理**: 快速失败给用户控制权,体验更好
5. **数据存储**: 本地存储保证数据安全,防止丢失

### 技术栈确认

- **前端框架**: 微信小程序原生框架(WXML/WXSS/JS)
- **API调用**: 封装在`api/index.js`,使用`wx.request()`
- **状态管理**: 页面级`data`,跨页面使用本地存储
- **错误处理**: try/catch + wx.showToast()
- **表单验证**: 前端基础验证 + 后端API验证

### 无需研究的主题

以下主题已有明确规范,无需进一步研究:

- 后端API规范: 已按RESTful标准实现
- 认证授权: JWT token机制已实现
- 数据模型: 后端已定义完整实体关系
- 字段验证: 后端使用Spring Validation

---

**结论**: 所有研究主题已完成,可以进入Phase 1设计阶段。
