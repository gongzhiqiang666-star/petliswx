# Feature Specification: PETLIS后端API服务

**Feature Branch**: `001-backend-service`
**Created**: 2025-12-27
**Status**: Draft
**Input**: User description: "要求完成后端服务的开发"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 微信用户认证与医院关联 (Priority: P1)

宠物医院工作人员使用微��小程序登录系统，系统验证身份并关联到对应医院，以便后续操作只能查看和管理本院的数据。

**Why this priority**: 系统必须知道"谁在用"以及"属于哪个医院"，这是所有业务操作的基础。没有认证，后续功能都无法进行权限控制。

**Independent Test**: 可以通过微信登录接口验证，返回有效的用户标识和医院ID，确保用户能成功登录且数据隔离正确。

**Acceptance Scenarios**:

1. **Given** 用户首次打开小程序，**When** 使用微信授权登录，**Then** 系统自动创建用户账号并关联到默认医院（或提示选择医院）
2. **Given** 用户已注册，**When** 再次登录，**Then** 系统识别用户身份并返回所属医院信息
3. **Given** 用户医院信息已变更，**When** 重新登录，**Then** 系统更新用户关联的医院

---

### User Story 2 - 宠物档案管理 (Priority: P1)

医院工作人员可以为宠物建立电子档案，包括基本信息（中英文姓名、物种、品种、性别、年龄、芯片号等）和主人信息，并支持查看、编辑和搜索宠物列表。

**Why this priority**: 宠物档案是送检流程的前提，所有检测申请都必须关联到具体宠物。这是核心业务实体。

**Independent Test**: 创建宠物后能在列表中看到，搜索能过滤出对应宠物，编辑能更新信息，证明完整CRUD功能可用。

**Acceptance Scenarios**:

1. **Given** 进入宠物建档页面，**When** 填写必填项（中英文名、物种、性别、生日、畜主中英文名）并保存，**Then** 宠物信息成功保存并显示在列表中
2. **Given** 宠物列表页面，**When** 输入宠物中文名或英文名搜索，**Then** 列表只显示匹配的宠物
3. **Given** 宠物列表��面，**When** 点击某个宠物的编辑按钮，**Then** 进入编辑页面并预填充该宠物的现有信息
4. **Given** 编辑宠物页面，**When** 修改信息并保存，**Then** 列表中的宠物信息已更新
5. **Given** 填写宠物信息时，**When** 未填写必填项（如中文名），**Then** 系统提示必填项不能为空

---

### User Story 3 - 检测申请与项目管理 (Priority: P1)

工作人员选择宠物和检测项目后提交检测申请，系统生成申请单并跟踪状态（草稿→待审核→等待报告→已完成），支持查看订单列表和详情。

**Why this priority**: 这是核心业务流程，送检申请是实验室系统的核心功能，涉及多表关联和状态流转。

**Independent Test**: 提交申请后能在订单列表中看到新订单，状态流转正确（从草稿到待审核），详情页能显示完整信息。

**Acceptance Scenarios**:

1. **Given** 选择宠物并选择检测项目，**When** 提交检测申请，**Then** 系统生成申请单，初始状态为"草稿"
2. **Given** 草稿状态的申请单，**When** 填写完整信息并提交审核，**Then** 申请单状态更新为"待审核"
3. **Given** 订单列表页面，**When** 按状态筛选（全部/待支付/进行中/已完成），**Then** 只显示对应状态的订单
4. **Given** 订单列表，**When** 点击某个订单查看详情，**Then** 显示该订单的完整信息（宠物信息、检测项、状态、价格等）
5. **Given** 申请单包含狂犬检测项目，**When** 提交申请，**Then** 系统验证芯片号和生日已填写，否则提示必填

---

### User Story 4 - 检测报告查询与展示 (Priority: P2)

工作人员可以查看已完成的检测报告，支持按宠物、日期、状态筛选，并在线查看或下载PDF报告。

**Why this priority**: 报告查看是送检流程的终点，用户需要获取检测结果。P2优先级是因为没有它也能完成申请，但业务价值显著。

**Independent Test**: 检测完成后能生成报告链接，报告列表能显示已完成的报告，点击能查看或下载。

**Acceptance Scenarios**:

1. **Given** 检测项目已完成，**When** 查看报告列表，**Then** 显示该项目的报告记录
2. **Given** 报告列表，**When** 筛选某个宠物，**Then** 只显示该宠物的报告
3. **Given** 报告列表，**When** 筛选状态（待出/已完成），**Then** 只显示对应状态的报告
4. **Given** 已完成的报告，**When** 点击查看，**Then** 显示报告详情或提供PDF下载链接
5. **Given** 检测未完成，**When** 查看报告列表，**Then** 状态显示为"检测中"且无法查看

---

### User Story 5 - 数据字典与配置管理 (Priority: P2)

系统提供基础数据接口，包括动物物种、品种、性别、样本类型、检测项目类型、城市等字典数据，支持前端动态渲染表单选项。

**Why this priority**: 前端需要从后端获取下拉选项数据，这是所有表单的基础。P2是因为可以用模拟数据暂时替代。

**Independent Test**: 调用字典接口返回有效的选项列表，前端能正确渲染下拉框。

**Acceptance Scenarios**:

1. **Given** 宠物建档页面加载，**When** 请求动物物种接口，**Then** 返回所有启用的物种列表（猫、狗、兔等）
2. **Given** 选择物种为"猫"，**When** 请求品种接口，**Then** 返回该物种下的所有品种（如英短、布偶等）
3. **Given** 性别下拉框，**When** 请求性别字典接口，**Then** 返回性别选项（未知、公、母、其他）
4. **Given** 检测项目选择页面，**When** 请求检测类型接口，**Then** 返回所有可用的检测项目（含价格、描述）
5. **Given** 字典数据包含禁用项，**When** 请求接口，**Then** 只返回IsActive=1的启用项

---

### User Story 6 - 用户信息管理 (Priority: P3)

用户可以查看和编辑个人信息，包括昵称、头像、所属医院等，支持退出登录。

**Why this priority**: 个人信息管理是辅助功能，不影响核心业务流程。

**Independent Test**: 修改个人信息后能保存，退出登录后需重新授权。

**Acceptance Scenarios**:

1. **Given** 我的页面，**When** 查看用户信息，**Then** 显示当前用户的昵称、头像、医院名称
2. **Given** 我的页面，**When** 点击编辑资料，**Then** 可以修改昵称和头像
3. **Given** 我的页面，**When** 点击退出登录，**Then** 清除本地登录状态并返回登录页

---

### Edge Cases

- **网络异常**: 当用户提交数据时网络中断，系统应提示错误并支持重试或本地缓存
- **并发编辑**: 两个用户同时编辑同一宠物档案，系统应采用后写覆盖策略并记录操作日志
- **数据权限**: 用户A只能查看所属医院的数据，尝试访问其他医院数据时返回403权限错误
- **必填项缺失**: 狂犬检测项目要求芯片号和生日必填，如果用户未填写应阻止提交并明确提示
- **状态流转错误**: 草稿状态的订单不能直接跳到"已完成"，必须经过"待审核"状态
- **删除操作**: 删除宠物时如果该宠物有关联的检测申请，应阻止删除或同时级联删除申请
- **价格变更**: 检测项目价格调整后，已提交的订单价格保持不变，新订单使用新价格
- **字典数据为空**: 当某个字典表为空时（如无品种数据），接口返回空数组而非错误

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持微信小程序用户登录，通过微信code换取用户唯一标识和会话凭证
- **FR-002**: 系统必须将用户账号关联到医院（lin_lb_infohospital表），每个用户只能属于一个医院
- **FR-003**: 系统必须提供宠物档案CRUD接口，支持创建、查询、更新、删除宠物信息
- **FR-004**: 系统必须在创建宠物时验证必填字段：中文名(AnimalName)、英文名(AnimalName_en)、物种(InfoAnimalId)、性别(DictSexId)、生日(Birthday)、畜主中文名(MasterName)、畜主英文名(MasterName_en)
- **FR-005**: 系统必须支持按宠物名称（中文或英文）模糊搜索，返回匹配的宠物列表
- **FR-006**: 系统必须提供检测申请创建接口，关联宠物、检测项目、采样信息等
- **FR-007**: 系统必须在创建检测申请时自动生成用户编号(UserNO)，格式为"55550-"前缀
- **FR-008**: 系统必须支持检测申请的状态流转：草稿(-2)→待审核(0)→等待报告(2)→已完成(3)，以及审核不通过(1)和已取消(4)
- **FR-009**: 系统必须在检测申请包含狂犬检测项目(InfoTestTypeId=1225)时，验证芯片号(ChipNO)和生日(Birthday)已填写，否则拒绝提交
- **FR-010**: 系统必须提供订单列表查询接口，支持按状态、时间范围、宠物筛选
- **FR-011**: 系统必须提供订单详情查询接口，返回主表(lin_lb_listdiagnosisproject)和明细表(lin_lb_diagnosisdetail)的完整信息
- **FR-012**: 系统必须在创建检测明细时，从价格表(lb_infotesttype_price)获取检测项价格，并计算总费用(TestFee)
- **FR-013**: 系统必须提供检测报告查询接口，返回已完成的检测报告列表
- **FR-014**: 系统必须在检测完成时生成PDF报告链接(PDFHttpUrl)，并提供下载接口
- **FR-015**: 系统必须提供数据字典接口，包括动物物种(lin_lb_infoanimal)、品种(lin_lb_infovariety)、性别(lin_lb_dictsex)、样本类型(lin_lb_infosampletype)、检测项目(lin_lb_infotesttype)、城市(lin_lb_city)
- **FR-016**: 系统必须在所有字典接口中只返回IsActive=1的启用数据
- **FR-017**: 系统必须支持品种按物种过滤，通过InfoAnimalId参数筛选对应品种
- **FR-018**: 系统必须提供用户信息查询和更新接口，支持修改昵称、头像
- **FR-019**: 系统必须实现基于医院的权限控制，用户只能查询和操作所属医院的数据
- **FR-020**: 系统必须对所有接口进行身份认证，未登录用户返回401错误
- **FR-021**: 系统必须记录关键业务操作的审计日志，包括订单创建、状态变更、支付操作
- **FR-022**: 系统必须对输入参数进行验证，包括长度、格式、必填项检查，防止非法数据
- **FR-023**: 系统必须使用逻辑删除(IsActive字段)替代物理删除，保留历史数据
- **FR-024**: 系统必须提供统一的错误响应格式，包含错误码、错误消息、详细信息

### Key Entities

- **宠物(Pet)**: 代表单个动物的档案信息，包含中英文名、物种ID、品种ID、性别ID、生日、年龄、体重、芯片号、畜主中英文名等属性，关联到动物物种表(lin_lb_infoanimal)、品种表(lin_lb_infovariety)、性别字典表(lin_lb_dictsex)

- **检测申请(Order)**: 代表一次送检申请单，包含申请单ID、用户编号、关联宠物、医院ID、城市ID、采样信息、样本状态、总费用、支付状态、创建时间等属性，关联到宠物档案、医院表(lin_lb_infohospital)、城市表(lin_lb_city)，状态流转为-2(草稿)→0(待审核)→2(等待报告)→3(已完成)

- **检测明细(OrderItem)**: 代表申请单中的具体检测项目，包含明细ID、关联申请单ID、检测项目ID、检测项目名称、原始价格、实际价格、折扣、报告结果、PDF链接、发送邮件状态等属性，关联到检测申请主表(lin_lb_listdiagnosisproject)和检测类型表(lin_lb_infotesttype)

- **检测报告(Report)**: 代表已完成的检测报告，包含报告ID、关联检测明细ID、报告结果内容、报告模板内容、PDF下载链接、生成时间等属性，关联到检测明细表(lin_lb_diagnosisdetail)

- **用户(User)**: 代表小程序用户，包含用户ID、微信openid、昵称、头像、关联医院ID、创建时间、登录时间等属性，关联到医院表(lin_lb_infohospital)

- **动物物种(AnimalSpecies)**: 字典实体，代表动物分类（猫、狗、兔等），包含物种ID、中文名、英文名、启用状态

- **品种(Variety)**: 字典实体，代表具体品种（如英短、金毛），包含品种ID、中文名、英文名、所属物种ID

- **检测项目(TestType)**: 字典实体，代表可检测的项目类型，包含项目ID、项目名称、项目编号、价格、报告模板、启用状态

- **医院(Hospital)**: 代表宠物医院，包含医院ID、医院名称(中英文)、地址、电话、联系方式、钱包余额、支付类型

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 微信用户从授权登录到进入首页的完整流程在3秒内完成
- **SC-002**: 宠物列表支持1000+宠物数据的流畅展示，搜索响应时间在500ms以内
- **SC-003**: 创建宠物档案的成功率达到99%，失败原因明确提示（如网络错误、必填项缺失）
- **SC-004**: 提交检测申请后，订单在1秒内出现在订单列表中
- **SC-005**: 订单详情页面加载时间在1秒以内，包含宠物信息、检测项、价格、状态
- **SC-006**: 系统能准确控制数据权限，用户无法访问其他医院的数据（通过测试用例验证）
- **SC-007**: 所有字典接口响应时间在200ms以内，支持前端快速渲染表单
- **SC-008**: 狂犬检测必填项验证准确率100%，未填写芯片号或生日时成功阻止提交
- **SC-009**: 订单状态流转正确率100%，草稿→待审核→等待报告→已完成按顺序推进
- **SC-010**: 检测报告生成后PDF链接可访问率100%，支持用户下载查看
- **SC-011**: API接口在正常负载下支持100并发请求，响应时间保持在1秒以内
- **SC-012**: 接口错误响应格式统一率100%，所有错误都包含code、message、data字段

## Assumptions

1. **微信登录**: 采用标准微信小程序登录流程，前端通过wx.login获取code，后端调用微信服务器换取openid和session_key
2. **医院关联**: 用户首次登录时关联到默认医院（如医院ID=1），后续版本支持多医院切换
3. **数据隔离**: 用户只能查看所属医院的数据，权限通过user表的hospital_id字段控制
4. **价格查询**: 检测项目价格从lin_lb_infotesttype_price表查询，支持不同城市不同价格，默认使用城市ID=0的价格
5. **状态管理**: 订单状态通过SampleStatus字段控制，状态机规则在前端和后端双重验证
6. **文件存储**: PDF报告存储在服务器本地文件系统或对象存储，URL通过PDFHttpUrl字段返回
7. **数据编码**: 所有字符串字段使用UTF-8编码，支持中文、英文、德文
8. **日期时间**: 日期字段使用LocalDate，日期时间字段使用LocalDateTime，统一转换为ISO格式返回前端
9. **分页查询**: 列表接口支持分页，默认每页20条，最大100条
10. **日志记录**: 关键操作日志记录到lin_admin_log表，包括操作人、操作时间、操作内容、IP地址
