# Feature Specification: PETLIS UX体验优化

**Feature ID**: 1-ux-improvement
**Status**: Draft
**Created**: 2025-12-28
**Priority**: High

## Overview

优化PETLIS宠物实验室信息系统微信小程序的用户体验,从宠物医院实际使用场景出发,简化操作流程,减少用户输入,提升整体易用性。

## Problem Statement

当前系统存在以下用户体验问题:

1. **宠物选择体验差**: 预约检测时选择宠物没有条件过滤,宠物数量多时查找困难
2. **重复数据录入**: 畜主信息在宠物维护中已存在,但预约时仍需手动录入
3. **年龄计算缺失**: 选择宠物后,年龄不会自动计算显示
4. **页面布局问题**: 多个子页面未居中,整体布局偏右
5. **物种选择体验差**: 直接使用picker,物种多时操作不便,缺少搜索和分页
6. **性别选择不明确**: 当前只显示"-"和"已绝育",实际应该有4个选项(未知/公/母/其他)
7. **宠物建档流程不合理**: 主人信息位置靠后,应该提到基本信息下面
8. **报告查看功能重复**: "查看完整报告"和"查看详情"功能重复
9. **报告查看缺少排序**: 不支持按申请时间、发布时间排序
10. **报告显示不完整**: 查看报告按钮未使用真实接口数据

## Clarifications

### Session 2025-12-28

- Q: 年龄计算使用哪个日期作为基准? → A: 当前日期(实时) - 始终基于今天的日期显示宠物的当前年龄
- Q: 搜索结果为空时如何处理? → A: 显示"未找到匹配结果"提示 + 提供清空搜索按钮返回全部列表
- Q: 搜索应该使用哪种触发方式? → A: 实时搜索(输入时自动触发) + 防抖300-500ms延迟
- Q: 畜主信息自动填充失败时如何处理? → A: 显示友好提示(如"畜主信息加载失败,请手动填写") + 允许用户继续操作
- Q: 是否需要宠物照片功能? → A: 不需要宠物照片功能,从规范中移除

## Goals

1. 提升宠物选择效率,支持搜索、过滤和分页
2. 消除重复数据录入,畜主信息自动带入
3. 实现年龄自动计算和显示
4. 修复所有页面布局问题,确保居中对齐
5. 改进物种选择体验,使用独立页面支持搜索和分页
6. 修正性别选择,提供完整的选项,通过后端服务获取字典
7. 优化宠物建档表单布局
8. 合并重复的报告查看功能
9. 增强报告列表功能,支持排序和分页
10. 使用真实API数据显示报告详情

## User Scenarios & Testing

### 场景1: 预约检测 - 宠物选择优化

**角色**: 宠物医院前台工作人员

**前置条件**:
- 系统中已有50+宠物档案
- 工作人员需要为"张三"的宠物"小白"预约检测

**操作流程**:
1. 点击首页"预约检测"按钮
2. 进入宠物选择页面,看到搜索框和筛选选项
3. 输入"小白"或"张三"进行搜索
4. 从搜索结果中选择正确的宠物
5. 查看宠物详情,包括自动计算的年龄(基于生日)
6. 畜主信息(张三)自动填充,无需手动录入
7. 继续完成后续预约流程

**预期结果**:
- 宠物搜索响应时间 < 1秒
- 显示搜索结果数量提示
- 宠物卡片显示: 宠物姓名、品种、主人姓名、年龄(自动计算)
- 畜主信息(姓名、电话)自动带入预约表单
- 支持编辑宠物信息(如果信息有误)

### 场景2: 物种选择 - 使用独立页面

**角色**: 宠物医院前台工作人员

**前置条件**:
- 系统中有100+个物种选项
- 工作人员需要为一只"暹罗猫"预约检测

**操作流程**:
1. 在宠物建档或预约页面,点击"物种"选择框
2. 跳转到物种选择独立页面
3. 页面顶部显示搜索框
4. 输入"猫"或"暹罗"进行搜索
5. 显示匹配的物种列表,分页显示(每页20条)
6. 点击选择"暹罗猫"
7. 返回上一页,物种信息已填充

**预期结果**:
- 物种选择页面独立展示,标题清晰
- 搜索实时过滤结果
- 分页加载,性能流畅
- 选中后有明显的视觉反馈
- 返回后正确显示选中的物种

### 场景3: 宠物建档 - 性别选择

**角色**: 宠物医院前台工作人员

**前置条件**:
- 新建宠物档案
- 需要填写宠物基本信息

**操作流程**:
1. 进入宠物建档页面
2. 填写宠物基本信息(姓名、物种、品种)
3. 填写主人信息(姓名、电话、地址) - 位于基本信息下方
4. 点击"性别"选择框
5. 弹出选择器
6. 选择"雄性"
7. 继续填写其他信息

**预期结果**:
- 性别选项清晰完整
- 选中的选项高亮显示
- 主人信息位置合理,在基本信息之后

### 场景4: 查看报告 - 优化列表和详情

**角色**: 宠物医院前台工作人员

**前置条件**:
- 系统中有200+个检测报告
- 工作人员需要查看"小白"的检测报告

**操作流程**:
1. 点击首页"查看报告"按钮
2. 进入报告列表页面
3. 看到排序选项:申请时间、发布时间(默认按申请时间倒序)
4. 切换到"发布时间"排序
5. 输入"小白"搜索宠物
6. 查看分页列表(每页20条)
7. 点击某个报告的"查看详情"按钮
8. 弹出报告详情弹窗,显示主要信息:
   - 宠物信息(姓名、品种、年龄、性别)
   - 检测项目列表
   - 检测结果概要
   - 报告日期、状态
9. 关闭弹窗,继续浏览列表

**预期结果**:
- 报告列表加载快速(< 1秒)
- 排序功能正常工作
- 搜索功能实时过滤
- 分页流畅
- 报告详情使用真实API数据
- 弹窗布局合理,信息层次清晰
- 只保留"查看详情"一个按钮

## Functional Requirements

### FR1: 宠物选择优化

**FR1.1**: 宠物选择页面必须提供搜索功能
- 支持按宠物姓名搜索
- 支持按主人姓名搜索
- **实时搜索**: 输入时自动触发,使用防抖机制(300-500ms延迟)
- 显示匹配数量提示
- **空结果处理**: 显示"未找到匹配宠物"提示 + 提供"清空搜索"按钮

**FR1.2**: 宠物列表必须支持分页
- 每页显示20个宠物
- 提供上一页/下一页导航
- 显示当前页/总页数

**FR1.3**: 宠物卡片必须显示关键信息
- 宠物姓名
- 品种
- 主人姓名
- 年龄(自动计算)

**FR1.4**: 年龄计算规则
- 根据宠物生日自动计算
- **使用当前日期作为计算基准**(实时显示宠物当前年龄)
- 显示格式: "X岁Y个月" 或 "X个月"(如果小于1岁)
- 如果没有生日信息,显示"未知"

**FR1.5**: 选择宠物后自动填充畜主信息
- 畜主姓名自动带入预约表单
- 畜主电话自动带入预约表单
- 畜主英文姓名自动带入预约表单
- 允许用户修改自动填充的信息
- **错误处理**: 如果API失败或数据不完整,显示友好提示("畜主信息加载失败,请手动填写") + 允许用户继续操作

**FR1.6**: 支持编辑宠物信息
- 宠物卡片上提供编辑按钮
- 点击后跳转到宠物编辑页面
- 编辑完成后返回宠物选择页面

### FR2: 物种选择优化

**FR2.1**: 物种选择使用独立页面
- 点击物种选择框后跳转到独立页面
- 页面标题:"选择物种"
- 提供返回按钮

**FR2.2**: 物种页面必须提供搜索功能
- 顶部固定搜索框
- **实时搜索**: 输入时自动触发,使用防抖机制(300-500ms延迟)
- 搜索结果高亮显示
- **空结果处理**: 显示"未找到匹配物种"提示 + 提供"清空搜索"按钮

**FR2.3**: 物种列表必须支持分页
- 每页显示20个物种
- 提供上一页/下一页导航
- 显示当前页/总页数

**FR2.4**: 物种项显示信息
- 物种名称(中文)
- 物种名称(英文)
- 点击整行选择

**FR2.5**: 选择反馈
- 选中的物种高亮显示
- 返回上一页后正确显示选中的物种

### FR3: 性别选择修正

**FR3.1**: 性别选择必须走后台服务获取

**FR3.2**: 性别选择使用picker组件
- 显示当前选中的性别
- 点击后弹出选择器

**FR3.3**: 默认值
- 新建宠物时默认选择"未知"

### FR4: 宠物建档表单布局优化

**FR4.1**: 表单字段顺序
1. 基本信息
   - 宠物姓名 *(必填)
   - 宠物姓名(英文) *(必填)
   - 物种 *(必填)
   - 品种 *(必填)
   - 性别 *(必填)
   - 生日
   - 芯片号

2. 主人信息 *(在基本信息下方)
   - 主人姓名 *(必填)
   - 主人姓名(英文) *(必填)
   - 联系电话
   - 地址

3. 其他信息
   - 备注

**FR4.2**: 表单验证
- 所有带 * 的字段必填
- 实时验证提示
- 提交前统一检查

### FR5: 页面布局居中修复

**FR5.1**: 所有页面必须居中对齐
- 使用flex布局或margin: 0 auto
- 最大宽度限制为750px(小程序标准宽度)
- 内容区域居中显示

**FR5.2**: 检查并修复的页面列表
- 宠物档案列表
- 预约检测页面
- 宠物建档页面
- 报告列表页面
- 报告详情页面
- 宠物选择页面
- 物种选择页面

### FR6: 报告查看功能优化

**FR6.1**: 报告列表功能
- 支持排序:申请时间、发布时间(默认申请时间倒序)
- 支持搜索:按宠物姓名,**实时搜索**(输入时自动触发,防抖300-500ms)
- 支持分页:每页20条
- **空结果处理**: 显示"未找到匹配报告"提示 + 提供"清空搜索"按钮
- 显示报告关键信息:
  - 宠物姓名
  - 检测项目数量
  - 申请时间
  - 发布时间(如果已发布)
  - 状态(草稿/待审核/已完成等)

**FR6.2**: 报告详情弹窗
- 点击"查看详情"按钮弹出
- 使用真实API数据
- 显示主要信息:
  - 宠物信息:姓名、品种、年龄、性别、生日
  - 检测项目列表:项目名称、价格、状态
  - 检测结果概要:文本描述
  - 报告信息:申请日期、发布日期、状态
  - 备注信息

**FR6.3**: 弹窗布局
- 居中显示
- 宽度90%最大宽度600px
- 提供关闭按钮
- 点击遮罩层关闭

**FR6.4**: 按钮优化
- 移除"查看完整报告"按钮
- 只保留"查看详情"按钮
- 按钮文案统一为"查看详情"

**FR6.5**: 排序功能
- 提供排序选项卡/下拉选择
- 支持申请时间排序(升序/降序)
- 支持发布时间排序(升序/降序)
- 记住用户选择的排序方式(本地存储)

### FR7: 性能优化

**FR7.1**: 搜索响应时间
- 本地搜索:< 500ms
- 远程搜索:< 1s

**FR7.2**: 列表加载性能
- 首屏加载:< 1s
- 分页切换:< 500ms

### FR8: 用户输入最小化

**FR8.1**: 自动填充
- 畜主信息自动带入(从宠物档案)
- 物种/品种联动选择
- 常用数据智能推荐

**FR8.2**: 智能默认值
- 采样日期默认为今天
- 采样类型默认为"血液"(最常用)
- 城市默认为医院所在城市

**FR8.3**: 历史记录
- 记住用户上次选择的采样类型
- 记住用户上次选择的送检医师
- 提供快捷选项

## Assumptions

1. **数据准备**: 系统中已有宠物档案、物种、品种等基础数据
2. **API支持**: 后端API已支持所需的查询、搜索、分页功能
3. **用户习惯**: 用户熟悉微信小程序基本操作
4. **网络环境**: 用户在稳定的网络环境下使用小程序
5. **设备性能**: 用户使用的设备性能足够支持流畅的动画和交互
6. **数据量**: 宠物档案数量 < 1000,物种数量 < 500,品种数量 < 2000
7. **权限控制**: 所有操作用户都有相应权限(无需考虑权限验证)
8. **数据同步**: 宠物信息、主人信息等数据实时同步

## Risks & Mitigations

### 风险1: 性能问题
**描述**: 大量数据情况下,搜索和分页可能性能下降
**影响**: 用户体验变差
**缓解措施**:
- 实现虚拟列表
- 使用分页加载
- 添加loading状态
- 优化API查询性能

### 风险2: 数据一致性和API失败
**描述**: 自动填充的信息可能因API失败或数据不完整导致加载失败
**影响**: 用户需要手动输入,体验降级
**缓解措施**:
- 友好的错误提示(如"畜主信息加载失败,请手动填写")
- 允许用户继续操作,不阻塞业务流程
- 提供手动输入选项作为降级方案
- 明确标识自动填充字段,方便用户识别和修改

### 风险3: 用户习惯改变
**描述**: 界面调整可能导致用户不适应
**影响**: 短期内用户投诉
**缓解措施**:
- 提供操作引导
- 保持核心流程不变
- 渐进式改进

### 风险4: API变更
**描述**: 后端API可能不满足前端需求
**影响**: 功能无法实现
**缓解措施**:
- 提前确认API能力
