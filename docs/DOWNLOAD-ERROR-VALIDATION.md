# 下载业务错误识别与认证范围

## 问题与修复（2026-11-08）

既有下载工具只检查HTTP状态，而BusinessException可能返回HTTP200+JSON code403/500，导致PC把错误保存为文件、小程序把错误临时路径交给阅读器。两端均已增加业务错误识别；HTTP/业务401触发过期登录处理，合法文件保持原下载路径。

PC按JSON响应类型识别错误信封，业务400–599转换为对应ApiError，JSON“操作成功”但无文件也拒绝；错误UTF-8文件名编码降级到普通文件名，不阻断有效下载。

小程序先检查下载文件存在及大小，最多读取512字节头部；疑似JSON仅在不超过64KiB时解析业务信封，拒绝不完整/过大错误响应和空文件。正常PDF、图片和CSV不整文件读入内存。不改变报告/发票的服务端鉴权规则。

附带修复：请求工具原先对绝对外部下载URL也附加登录令牌。现在仅与配置API同源时附带认证，外部历史链接不携带令牌。外部情形只在单元测试检查请求参数，没有实际请求第三方网站；未验证跨域重定向或真实历史供应商下载。

错误临时文件在平台允许时尽力移除；微信开发者工具的http://tmp路径实际为只读，unlink被拒绝，这些临时缓存交给SDK回收。不能宣称全部错误缓存已主动删除，但它们不再作为成功文件返回。没有绕过工具文件权限删除缓存。
