## 并行运行修订（2026-11-07，覆盖上文“独立链路”验收方式）

新系统与原 PHP 必须同时运行，同一业务单据支持双向状态同步、跨端接续。不能只验证旧数据展示，或用两份互不相关订单分别跑通来代替并行验收。W1 起逐段检查 PHP，W4 做集中混合流程回归。

### 数据与状态同步原则

1. 优先复用原业务主表、订单和明细 ID。新增 lin_业务名 表保存扩展、映射、版本、审计及幂等信息，不能复制成两份独立订单。异库部署需要另做同步设计，不能套用同库验证结论。
2. W1 交付字段/枚举映射表：实体、旧字段、旧/新状态、权威来源、允许转换、触发端、另一端读取/写入方式、同步时点、失败补偿及对账方法。审核、支付、物流、检测、报告分别建状态机，不互相覆盖。
3. 同库核心字段提交成功后，另一端下一次刷新应一致；新扩展数据需为 PHP 补适配入口，保证可读并按权限接续。旧端缺功能不能直接跳过验收。缺历史数据不得虚构物流节点、审核、结果或支付成功。
4. 并发、重复和乱序操作必须明确冲突处理；不能按最后写入时间覆盖已支付或已审核结果。下单、扣款、签收、建任务、发布和通知以共享业务键去重。报告文件、版本、撤回与权限同时同步。
5. 本机定时任务继续关闭。需后台处理的同步使用受控手动入口，显示待同步/失败原因，保留重试与对账记录。手动同步完成后刷新一致；自动同步延迟目标须在用户允许开启调度后另行约定和测量。

- 运单与标签：获取电子面单/标签，支持授权查看、打印与失败后重取；标本条码和运单号分别保留，支持一运单多标本的关联，不将两种编号混用。面单含个人信息，禁止公开文件地址及在日志中输出完整地址电话。
- 变更与取消：按顺丰支持及订单实际状态实现取消、预约变更；业务订单取消和承运订单取消分别处理，失败明确提示，不把单方成功显示成全部成功。
- 物流追踪：路由查询、订阅及回调，保留原始路由码、事件发生时间和接收时间，映射揽收、在途、派送、签收、异常及取消；物流签收不等同实验室核样通过。
- 异常与补偿：下单超时先查询核对，不盲目重下；回调验签/来源认证按官方协议实现；重复与乱序去重，失败入可查询记录，支持授权手动补偿和对账；不因旧路由覆盖已完成业务状态。
- 权限：医生只操作本医院的合格订单，配送和实验室按角色范围查询；接入账号、付款方式、费用承担及可用产品由业务配置，不在代码写死。

### 新旧系统并行适配

以同一业务单据、顺丰订单及运单关联为准，新 PC、PHP 和小程序都能看到一致的运单、最新路由与异常。新端下单后 PHP 能查询、打印和按权限接续；PHP 发起寄件后新端和小程序同步可读。若旧 PHP 没有顺丰入口，增加应用适配入口，不能跳过旧端验收或用第二张运单替代。

共用幂等键避免双端重复寄件；回调只处理一次业务事件，不重复通知。物流路由到达不直接更新报告或财务状态。旧表缺少字段时优先通过已批准扩展表的关联解决；确需修改原结构，先提交理由、精确 SQL、兼容性与回滚方案，由用户同意后实施。
