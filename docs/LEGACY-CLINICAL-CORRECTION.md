# PHP 受管送检资料修正

只在 Petlis 本机运行副本安装，统一调用 Java API；参考 PHP 源码、Mac mini 原库和其他项目不改动。不执行 DDL，不开放旧模型直接写入。

## 使用流程

PHP 后台打开受管送检单，进入同单全链路页，展开“修正送检与临床资料”。填写资料和必填修正原因。待审核单保存后保留待审核；审核未通过单可选择“仅保存”或“保存并重新送审”，重提后由统一审核入口处理。

当前支持宠物中英文名、体重、芯片、年龄、采样部位、畜主中英文名、医生姓名文字、备注、既往病史、临床症状、临床诊断、用药情况。身份归属字段不随文字更改；医生姓名文字修正不会重新绑定医生账号。普通字段最多250字，四项临床文字最多2000字；变化后的年龄使用3Y7M/5M/3Y格式。狂犬检测芯片和备注必填，备注同步到该检测项目的原明细备注，不改其单价或ID。

本次送检快照和宠物档案分开：不直接覆盖宠物档案。原送检ID、条码、医院、医生账号、物种/品种/性别/生日、采样类型和日期、实验室、项目、价格、优惠与计价快照保持不变。需要改这些字段的完整重提和核价仍按医生端流程处理，本入口不是所有业务字段的自由编辑器。

## 状态与并发

- 仅管理员写入；读取按医院或实验室范围授权。
- 只接受有扩展记录、未支付、待审核/审核未通过且审核扩展匹配的单据。
- 已有任何物流、实验室任务、报告或检测/结算明细状态的单据拒绝直接改写。
- 前后资料、状态、扩展时间、临床更新时间和修正审计序号生成版本摘要；事务先锁原订单，再锁临床和修正版本。旧摘要不能覆盖新修改，资料A→B→A也不复活旧版本。
- 两份相同版本并发保存只有一份成功，另一份409并要求刷新核对。失败不会部分修改金额、明细或审核状态。
- 每次成功修正保留 `LEGACY_CLINICAL_UPDATED` 的前后资料和原因。PHP 操作另有原管理员来源及确认状态审计。
- 重新送审保留核价和项目，清除旧审核决定并转待审核，通过现有触发器关联通知去重；不改触发器定义。

## 接口与页面

- `GET /api/orders/{id}/clinical`：医生端读取本次送检临床资料，范围校验。
- `GET /api/legacy/orders/{id}/clinical`：共享页读取资料及可编辑状态。
- `POST /api/legacy/orders/{id}/clinical`：管理员提交 `{version, fields, reason, resubmit}`，fields必须是完整允许字段集合。
- 小程序订单详情显示四项临床资料，加载失败使用独立重试，不阻断订单主体；同时修正原订单重试把点击事件对象作为订单ID发送的问题。
- PHP 表单保留原登录、超级管理员检查及CSRF；桥接只使用固定本机API，不支持任意URL。控制器显式将查询单号转换为整数后交给桥接。

## 健康档案500排错记录（investigate）

症状：临床修正已能被医生订单和临床接口读取，访问宠物健康档案却500。

根因：PetHealthService报表查询使用 `d.SendReportDt`，原明细表实际只有 `SendMailDt`；隔离库列元数据、实体映射、已有合成报告发送时间与运行错误堆栈一致确认。

修复：应用查询改为 `d.SendMailDt AS sendReportDt`；不新增列、不改视图或触发器。

回归：`test-real-flow-fix.py --php-clinical` 在修复前真实HTTP失败于健康档案，在修复后完成资料修正、健康档案读取、审核、物流、实验室、报告发布和鉴权PDF全链。
