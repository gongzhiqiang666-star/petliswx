# 顺丰再次寄件后端与官方沙箱验证（2026-11-08）

## 实现与控制

再次寄件接口POST /logistics/sf/orders/{orderId}/reship，仅ADMIN；必须引用前一次成功CREATE的ID及原因，并提交完整寄收件资料。全局运营参数sf-reship默认关闭，enabled必须为JSON布尔true；maxAttempts默认3，允许2至10，硬上限10。未开启时直接API拒绝409，普通医生403；关开关不阻止已发请求的查询与本地绑定恢复。

每次请求由(order_id,attempt_no,operation)唯一。首单外部号保持PETLIS_SANDBOX_订单ID，后续追加_A次数；原因和前次ID参加CREATE幂等摘要，相同前序更改联系人/地址/原因不再次下单。预留事务锁订单，严格校验已审核/付款或月结状态、当前前次已取消且同外部订单号的CANCEL为SUCCEEDED、未检测/报告/退款和前序未过期；留下SF_RESHIP_RESERVED审计。网络在事务外，只有RESERVED可取得一次发送权，SENDING/UNKNOWN只能查询原号。

成功主运单由短事务绑定。重复绑定不建新行/通知；旧当前标识置NULL，原状态/单号/版本/更新时间保留，新运单使用独立ID。约束异常回滚当前标识，成功请求仍持久化，不能因本地失败重发。每次取消使用本次外部号；旧取消不阻止新面单/路由，历史面单仍撤权、历史运单拒绝写操作。当前与历史读取覆盖Java、小程序、PC及本机PHP覆盖层，参考PHP原源码未改。
