# 物流异常事件与去重

原实现所有异常共用 `shipment:{id}:EXCEPTION` 消息键，后续不同异常可能只写时间线、不再形成新医生通知；重复提交又会反复写时间线。现按独立异常事件保存和通知。

## 实现

- `POST /api/logistics/{id}/exception` 新增可选requestKey（16–64位字母数字下划线短横线），既有exceptionType/note/reason兼容。
- PC提供标本破损DAMAGE、标本丢失LOSS、超时DELAY、其他OTHER，弹窗生命周期内保持同一请求号；旧客户端不传时，用类型/说明长度前缀编码的SHA256生成64位稳定键。
- 先核对当前配送员及运单归属，锁运单，在审计表按运单/动作/请求号做当前读。同号同内容只读返回，同号改内容409；不同请求独立记录。
- 复用lin_audit_record的request_id与after_json，保存类型和完整说明；不增表/索引。通知键使用新审计ID，每个独立异常一条消息，重试不重复。
- 不改变原运输状态；登记允许待揽收、已揽收、运输中和已送达。签收/取消后不新增异常，历史成功请求仍可只读重放。
- note最多1000、类型最多32字符，避免数据库截断。通知使用含中文类型的有界摘要，完整说明仍保存在运单/审计；Unicode截断不拆分代理对。
- 医生端异常类型显示中文，时间线与消息中心可看当前说明和历史事件。

## 逐条异常处理与新旧端同步（2026-11-08）

新增 `POST /api/logistics/{shipmentId}/exceptions/{eventId}/resolve`，必填处理说明（最多1000字）。ADMIN、所属实验室LAB_STAFF或当前分配COURIER可操作；医生无操作权限。锁运单并验证事件所属运单，按不可变事件ID防重复。相同说明重放只读返回，不同说明409；跨运单事件404。使用READ_COMMITTED读取处理后的当前视图，避免等待锁后返回旧快照。

复用审计记录EXCEPTION_RESOLVED，保留处理人/时间/说明和来源事件ID。处理后寻找最新未处理异常并维持当前预警；全部处理后清除当前exception_type/note/at，运输状态保留，原异常和处理历史不删。每次有效处理独立通知医生，重放不发新消息。API显式返回resolved标志，兼容全局序列化省略null字段。

PC时间线提供逐条处理说明入口及历史；小程序只读展示报告/处理状态和说明。PHP共享页增加同一事件的处理表单，继续要求原超级管理员、登录、CSRF及私有ADMIN映射；桥接从订单推导运单，不接受客户端替换运单ID，并保留PHP管理员身份。PHP新旧端读取同一审计事件，没有复制业务数据。
